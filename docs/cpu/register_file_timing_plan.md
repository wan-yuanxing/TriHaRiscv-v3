# CPU 分布式寄存器堆时序实施计划

> 执行方式：使用 executing-plans，单代理逐项执行。沿用已授权六级单发射、100MHz、Windows工具约束；不创建新工作树、不合并主工程、不编程板卡。

**Goal:** 针对第9轮真实的寄存器堆读出/JALR关键路径，验证Pango异步读分布式RAM实现是否能在保持指令周期的同时改善100MHz时序。

**Architecture:** 单发射配置使用两份32×32单写异步读RAM，各服务一个读口，共享一份31位已写标记。同步reset清除标记，掩盖RAM残留数据，x0恒零；不增加读延迟。次写口在单发射核中必须为0，仿真断言检查该集成契约；双发射保留当前已测通用实现。

**Tech Stack:** Windows PowerShell7、已有Python、ModelSim2020.4、PDS2022.2-SP6.4、现有RISC-V GCC。原语使用GTP_RAM32X2DP；ModelSim读取安装目录的原模型，独立哈希绑定，不在仓库复制工具模型。

## 选择与边界

- 继续FF加分层mux：保持通用，但仍有992个数据FF与大读mux，不能直接消除当前读地址高扇出。
- 异步读分布式RAM：保留周期和两个读口，适合本器件；需正确处理没有运行时清零端口和单写限制。本轮选择此项。
- 同步block RAM：需要移动读时序或增加寄存级，验证范围及性能代价更大，本轮不采用。

已有FPGA寄存器堆结构及原语来源只记录在适配/工具清单，原始vendor文件与许可保持不变。次读口在单发射配置不使用，输出0。次写口非零属于非法集成输入，不声称单写RAM实现通用双写行为。

## 文件责任

- `rtl/cpu/triha_regfile.v`：单发射原语实现与双发射回退连接。
- `rtl/cpu/triha_issue.v`、`ADAPTATIONS.json`、显式仿真/PDS filelist：接入及哈希绑定。
- `config/cpu_primitives.json`、`scripts/cpu/simulation_common.ps1`：已安装仿真模型的路径/哈希及读取，不新增安装环境。
- 四个ModelSim入口：记录并复核外部模型哈希，传入真实模型。
- `tb/cpu/tb_regfile.v`及组件入口：独立寄存器数组oracle、x0、无读延迟、同址写后读、连续写、同步复位和热复位、实际损坏负例。

## 步骤

- [ ] 冻结现有通用寄存器堆的组件map，确认没有分布式RAM、约992数据FF，以资源目标测试记录RED。
- [ ] 写独立组件自检，在原实现核对已有语义，建立可拒绝真实数据损坏的测试。
- [ ] 最小实现原语后端及31位复位可见标记；用真实工具模型验证组件，核对实际PDS分布式RAM映射及FF不超过64。
- [ ] 接入单发射CPU及原语模型哈希记录；断言次写口为零。运行三种种子×两模式逐周期/按序异常、IRQ、请求保持/fault、故障注入。
- [ ] 同ELF CoreMark两模式、startup/retire/validation/冒烟；逐项报告周期/CRC，不预设等周期。
- [ ] 原10ns及原IO/hold/multicorner、同区域完整新PDS实现。核对输入输出哈希及最终六项时序，只在全部满足时称100MHz通过。
- [ ] 保存证据、性能和CPU-only面积；提交小范围变更，保持历史失败记录，不自动合并。

本计划不包括正式SoC地址/DDR/Video变更、板级下载或完整ISA认证。若组件/整核/物理验证失败，依据实际失败原因处理，不用模型PASS替代器件时序。
