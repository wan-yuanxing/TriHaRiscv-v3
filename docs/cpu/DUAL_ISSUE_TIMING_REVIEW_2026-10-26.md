# 双发射时序收敛复盘

本路线尚未完成用户要求。SRAM 的 `-O2` 短测超过4 CoreMark/MHz，但没有任何一版同时通过原100MHz后布线验收。多次局部改动没有形成可靠收敛，执行方法需要纠正。功能测试和证据核验有价值，不能当作时序进展。

全部面积仅取CPU核层级；分布式RAM LUT已经包含在LUT总数中。物理完成版使用原10ns、IO、hold及多corner约束；表中的负setup均为失败。v60不能从工具成功标记推断进程退出0。v61/v62原生退出0、验收器退出2，分别核验292/500个输出及全部冻结输入。

v57至v62的六字SRAM短测均为1221907周期、4.091964/MHz，WB观察IPC1.185400。v63为1224859周期、4.082102/MHz，周期增加2952（0.241590%）。两者都只是五次迭代RTL估计，非官方或板级分数。v63仅归一化经过指令/ELF符号确认的首个cycle CSR读值及其started存储，其余1448447条WB、70838条store逐行完全相同；未忽略其他差异。

## 为什么现有方法低效

1. **没有及时冻结整体时序问题。** 名义六级仍包含RF/旁路、配对许可、晚出队和宽FIFO更新之间的长控制链。局部等价改写不能替代这些边界的设计。
2. **物理试验承担了过多筛选任务。** 去掉carry、减少逻辑级、增加复制或消除CE之后，没有充分限制新增扇出、控制组、数据复制和布局成本，因而“局部成功、全局回退”反复发生。
3. **没有严格执行结构方案的淘汰预算。** 不同局部变体造成不同映射/布局，最差路径不断转移。继续派生版本不能证明正在接近可部署结果。最佳值差9ps也不构成时序通过。

实际证据说明瓶颈反复落在共同的控制/存储耦合上：v57队头PC连续性经调度进入FIFO数据写口；v59乘法值经零判断/配对进入FIFO；v60分支恢复/异常进入FIFO；v61 ROM/LSU返回经配对进入FIFO；v62复位输入经data_accept/issue进入696负载的出队网络。不同版本的具体最差路径不能直接相加或当成同一布局的收益。

## 后续执行边界

首先保留v57作为可重建的物理基线，v63只作为已完成的容量/性能对照。当前不直接启动下一次完整PDS，不继续扫种子、叠加综合属性或将失败候选提升到默认RTL。

下一步先完成一次设计审查，比较以下两种有明确边界的选择：

- **保留当前结构，评估五字队列。** 当前只损失0.242%的短测周期，仍超过4/MHz；先用原生综合核对实际存储数、晚控制网络连接数、控制组及关键组合深度。它尚不能被认定为时序修复；只有结构门槛有实证改善才值得一次布线。
- **重构取指队列的存储组织。** 将队头两字保留在寄存器，后部存储只因入队写入，出队只控制队头/指针，避免每次发射搬动整队宽载荷。必须先解决同周期入出队、空队输入旁路、B-only保留、flush、预测/fault/CSR侧带和invalid元数据历史。它是待审查方案，没有实现或性能承诺。

对下一结构方案预先固定门槛：

1. 画清楚每条寄存器到寄存器的控制链，给组合逻辑及布线预留预算；工程目标是留下正余量，最终判定仍使用原100MHz全部corner实际STA。
2. 综合后检查真实连接，不能只凭属性识别、RTL行数或局部逻辑深度。新增高扇出、复制寄存器和宽mux必须列入成本；局部优化不得掩盖新的全局瓶颈。
3. 功能与性能测试先行；允许披露并接受小幅配对/容量代价，但新版本必须实测超过4/MHz，不放宽编译参数，不以不同内存边界替代比较。
4. 一个已审查结构最多安排两轮有明确归因的完整物理试验；首轮没有预期改善时先复盘，不能直接开启第三个小变体。出现新关键路径不自动构成继续叠加补丁的理由。
5. 只有冻结输入/输出、真实退出码和Slow/Fast setup、hold、脉宽全部通过才接受。默认CPU、主工程集成及板卡仍保持独立。

现有已上板单发射路线继续作为SoC集成基础。双发射独立路线不能以尚未通过的分数/时序替代该部署基线，也不能阻塞其集成工作。
