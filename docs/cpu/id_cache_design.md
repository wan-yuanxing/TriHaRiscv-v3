# CPU I/D Cache subsystem design

## Contract

- RV32IM/CSR, single issue, six main stages, BTB512/BHT512/RAS4, GShare off remain unchanged. Cache wait cycles use existing request/accept/completion stalls; no speculative early-load forwarding.
- I and D each contain 16KiB, two ways, 256 sets, 32-byte lines. Data and tag memories use synchronous read-first storage and explicit Pango block-RAM inference. Valid state must initialize without resetting the data array. Both caches ship in the same subsystem; neither is described as finished merely because its component simulation passes.
- Only `0x80000000..0x81ffffff` is cacheable CPU-private DDR. `0x82000000..0x87ffffff` is uncached shared DDR. ROM/SRAM retain their existing local paths; MMIO remains uncached. No cached alias of a shared region. Cacheability is checked at the subsystem boundary even if the CPU supplies a permissive attribute.
- D is blocking, write-through, no write allocate. Every store completes only after the lower write response; successful hit stores update the resident word with byte enables; failing hit stores invalidate the resident line and return an error. A write miss does not refill or allocate. No dirty state, writeback eviction or posted store completion is admitted.
- Read misses install a line only after all advertised beats complete successfully. Partial/failing refills remain invalid. CPU response tags are preserved. Maintenance commands complete through the normal handshake; reset is coordinated with CPU and fabric, never used to discard accepted live AXI traffic.
- I flush/invalidate must prevent stale refill publication. Validate FENCE.I with modified instructions and pending fetches before claiming instruction synchronization support. D invalidate/flush are clean-cache operations; writeback is an acknowledged no-dirty operation after prior transactions drain.
- Lower DDR boundary is the existing 128-bit AXI contract: 16B-aligned full-width transfers, 32-bit byte addresses, 4-bit IDs, INCR, no 4KiB crossing. A 32B refill occupies two 128-bit beats. A scalar write occupies one aligned beat with its exact byte strobes; no unprotected read-modify-write. Requests remain stable under backpressure; response IDs, errors, beat counts and LAST are checked. Existing Video/native DDR implementation is not copied or changed.

## Local system boundary

`triha_cached_soc` is the opt-in ROM-reset system target; it instantiates the unchanged CPU and `triha_cpu_memory_router`. The router retains `triha_soc_memory` for ROM/SRAM/UART/System and `triha_cache_subsystem` for DDR. Each CPU bus records its response owner and pending count on acceptance. Requests to a different target wait until all old responses drain; response selection never uses the live address. The selected return data is an owned mux, not an OR of stale memory outputs. Same-target local requests retain pipelined acceptance; counts are bounded to avoid overflow.

System address `0x2002000c` is a read-only DDR status extension, generated together for RTL/C: bit0 ready, bit1 sticky fault. The pre-existing +0/+4/+8 registers are unchanged. New DDR requests stall before initialization; after a platform/protocol fault they receive owned synthetic access errors. Local code/status still works. Maintenance goes to Cache even with address zero and before DDR ready. Flush/invalidate instruction pulses remain connected when local code is executing. The router gates only new CPU request qualifiers; it never masks cache-side pending requests, AXI VALID or late responses. A failed bridge that never retires traffic can still require coordinated reset; there is no promise of bounded software recovery from every fatal in-flight fault.

All signals at this boundary, including DDR ready/fault, must already be synchronized to the supplied CPU clock. It does not directly connect the actual125MHz DDR port. A reviewed asynchronous AXI boundary and one version-bound shared DDR owner are required before production integration. A ready/fault event must not reset a FIFO, Cache or bridge independently. Physical timing must include the actual system/CDC/fabric boundary; serial observation fixtures are area-only.

## CPU / DDR clock boundary

`triha_axi128_cdc` provides five independent queues: AW49bits, W145bits, B6bits, AR49bits and R135bits. Each reuses the immutable synchronous-read Gray-pointer FIFO with four RAM entries plus its held output register. Payload includes every supported address/ID/LEN/SIZE/BURST/strobe/LAST/response bit. Queues preserve each channel's order and hold VALID/payload under backpressure; they do not change AXI completion semantics or acknowledge CPU stores. DDR ready/fault pass through two-stage CPU-domain status synchronizers. They never clear queues or mask accepted VALID.

The single `rst_ni` input starts a coordinated epoch; CPU and DDR each asynchronously assert and synchronously release their local reset pipe. The enclosing CPU/cache/bridge/controller must share this epoch. A separately reset controller or stopped clock is outside normal recovery: external supervision and coordinated reset may be needed. There is no promise that an unresponsive native transaction can always be converted to a bounded software error.

`triha_cpu_ddr` composes the unchanged local cached system, this clock boundary and the pinned AXI128/native256 bridge at125MHz. The native port has exactly one owner through write/readback verification. Successful CPU writes still wait for the bridge B response after observed masked readback. This wrapper is an opt-in exclusive CPU boundary; CPU/NPU/Video arbitration must be inserted upstream of that bridge, never between native write and verification. Immutable Git extraction, hashes, installed-tool commands and native area are bound per run. Analog DDR training, Gray-bus physical skew/delay constraints, synchronizer placement and actual100MHz post-route timing are separate admission gates.
