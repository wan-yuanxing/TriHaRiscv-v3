# 同步乘法零标志实施计划

目标：原100MHz、六级双发射和-O2 SRAM/TCM短测>4/MHz不变。用户已确认继续同步零标志路线。默认RTL和集成工程不变。

设计：在现有乘法操作数E1采样边界增加一个零标志寄存器，复用原异步复位/hold条件；无符号16×16完整低乘积为零当且仅当任一16位输入为零。未知低位输入时仿真保留乘法全X导致的未知零判断，不能让0×X变成确定零。通过CPU连线到issue，复用forward_raw_zero；仅将E1来源的零比较从宽数据mux之后移到两侧，未知选择时仍使用旧向量合并比较。数据路径和tag优先级不改。

替代方案：仅做组合预比较仍等待APM输出，预计改善有限；增加stall可截断路径但损失性能，暂不采用。

- [x] 先建立独立乘法oracle，涵盖所有16位值的零边界、随机乘积、hold/reset/X/Z；错误零标志负例必须失败。
- [x] 实现隔离候选及端到端连线，验证两路零比较与原32位数据比较一致。
- [x] 完整CPU CoreMark及WB/store轨迹对照；生成可重建补丁和输入清单。
- [x] 原生映射核对APM到零比较依赖是否消除，以及新输入到零寄存器路径、资源和扇出成本。
- [x] 独立复审后才能决定一次原约束物理验收。局部仿真PASS不代表时序PASS。

组件206622检查；双路E1消费者8000检查和X/Z向量合并反例；真实侧带破坏被消费者检出。实际程序191周期，A/B乘法25/23，hold72拍。统一重放scripts/cpu/check_mul_zero.py的最终结果PASS。
