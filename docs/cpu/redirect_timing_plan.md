# CPU 寄存重定向实施计划

目标：切断已由实际STA确认的重定向→预测→下一PC组合路径，保持六级主流水和原100MHz约束。

使用现有取指模块的寄存重定向分支，前端独立选择该时序机制；外层MMU仍关闭。原始文件保持字节不变，仅维护前端派生连接。寄存重定向会增加恢复延迟，必须实测CoreMark，不能预设等周期。

- [x] 建立前端测试，旧连接必须因同周期PC绕过而失败。覆盖复位、在途返回、请求/输出背压、连续重定向和废弃响应。
- [x] 新增有独立延迟存储响应的控制测试。同步异常模式记录按序WB载荷、异常和store，与原核比较；异步IRQ单独自检，不要求不同时序的IRQ拥有相同mepc。
- [x] 增加最小前端派生及多文件哈希清单。保留REGISTER_REDIRECT=0旧路径逐周期测试，新默认路径使用独立按序验证。
- [x] 运行三个背压种子×单/双模式、IRQ、故意破坏负例，及startup、14指令探针、CoreMark性能/CRC。
- [x] 运行原配方原约束的有界PDS完整流程，核对六项实际Slow/Fast时序与所有输入/输出哈希。
- [x] 保存结果、性能代价和适用边界，提交CPU自有文件，不自动合并主工程。

三轮实际后布线已结束；第三轮setup -5.918/-0.712ns，仍未收敛。完成本批验证不等于完成100MHz目标，下一批以真实BTB训练更新关键路径为依据。

第一轮实际布通后setup为Slow/Fast -7.577/-1.724ns，最差路径转到issue载荷选择。第二个独立改动仅把opcode/PC/fault载荷按已注册PC和fetch有效信息选择，取消/异常仍门控原发射有效位，不增加周期。`tb_issue_payload.v`先证明旧版会在取消时改动opcode，修改后检查数据保持、有效关闭。原逐周期miter始终比较请求控制、所有有效/停顿中的数据载荷、WB、预测及CSR；空闲地址不作为事务载荷，`-CompareIdleBus`保留旧严格诊断并预期暴露无请求时0→0x14差异。同步异常的新独立存储/按序对照不因此减弱。

第二轮setup为-7.776/-1.923ns，CPU-only LUT7744→8072，未改善全局最差时序。实际新路径终止于APM输入与CSR宽数据寄存器。第三轮在相同issue数据选择基础上，让乘法器/CSR宽数据按已有执行模块的方式独立采样，保留有效、异常、CSR读副作用与提交写控制。`tb_unit_payload.v`的两类RED均观察到旧零化路径，修改后通过；`tb_multiplier_payload.v`对四种乘法、气泡及hold作独立整数模型校验，129次值检查/42次hold，实际错误结果负例被拒绝。三组整核事务逐周期对照和独立按序对照通过；CoreMark与第一轮完全等周期、等CRC。最终时序仍须以第三轮实际报告判断，不把局部逻辑改善视为全局收益。

入口：`scripts/cpu/run_redirect.ps1`、`run_equivalence.ps1`、`run_firmware.ps1`、`run_route.ps1`。失败先按实际日志定位；不降低时钟、不改写历史证据、不编程板卡。
