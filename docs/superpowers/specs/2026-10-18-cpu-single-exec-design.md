# Single-issue execution specialization

执行用户确认的单发射残留逻辑核对与裁剪。保持六级、ISA、预测器、旁路、CSR和总线时序不变，仅在`SUPPORT_DUAL_ISSUE=0`时不生成第二执行单元。双发射使用原执行单元。第二流水控制含无条件接入的共享CSR结果/异常，不能按模块名直接删除，本阶段保留。

原始vendor文件不修改。新增直接维护的Verilog内部连接文件`rtl/cpu/triha_cpu.v`，从固定内部连接源码派生，只改模块名和第二执行单元的条件生成；许可保留，差异单独记入`rtl/cpu/ADAPTATIONS.json`。生产封装仍为`triha_core`，仿真和综合明确选择派生连接，原始连接仅供对照验证。

单发射时第二执行单元输出为零。依据是第二发射valid恒为0；复位后第二单元分支状态保持0；第二路写回寄存器地址与分支/访存/乘法有效控制为0，因此其ALU数据不能写入架构状态。CSR/异常广播及取消控制保持原逻辑；对照必须覆盖这些依赖，不能只对比CoreMark最终CRC。

验证采用Windows ModelSim，逐周期比较父版/候选总线、真实WB事件、分支预测更新和CSR异常状态，加入确定性背压、访存错误、非法指令/ECALL/EBREAK、访存未对齐、IRQ及mret定向程序。保留正常TCM下CoreMark单/双两模式复测。故意破坏双发射第二路写回应被对照检测。该范围属于定向/差分仿真，不称完整ISA或形式证明。

通过后运行CPU-only Pango综合/映射，核对单发射第二执行单元不再存在与实际LUT/FF变化，双发射不得意外裁掉。原100MHz目标不降低；当前阶段没有后布线频率结论。
