# F4c3a Video共享DDR端口调度与并行联测

继续用户授权的Video实现。本批增加Video局部采集写/显示读调度，不改CPU正式fabric、
公共地址、旧ABI或厂商DDR桥；不把数字readback等同于系统跨master可见性。

## 选择

现有桥AW优先，单独把写/读接到不同AXI通道会使连续写长期压住读。采用一个显式
单事务调度器，在桥前选择capture AW或display AR，并把完整描述符同步保持。
相比改桥内部仲裁，它保留已验收桥；相比两套native桥，它维持唯一native所有者和
写后核验独占。调度器不缓存帧/像素，不重新分配ID，也不成为全局帧所有者。

每次最多接纳一个总事务。请求在本地接纳后，公开下游地址和有效位保持到真实
桥接纳；capture W仅在写地址接纳后传送。写占有到B握手，读占有到ARLEN+1个R
握手；不使用可损坏的RLAST作为提前释放证明。所有响应原样回到唯一方向主端。
两条响应路径不可同时归属；未经接纳的W不能穿过。

## 服务策略

普通竞争按上次grant交替；display_urgent=1时读优先，但capture等待时最多连续
`MAX_READ_BURSTS`个读事务（默认4，允许1..16），之后必须服务写。仅读时不闲置。
计数在grant更新，背压时不新增grant。急迫信号由未来真实水位生产者提供；本批
联测把它固定为1，验证持续读优先下写仍有进展，不冒称自适应水位/QoS已实现。

上界以已完成事务数表述，前提是native、W供数和B/RREADY继续前进。不能抢占已
发布事务，任意外部停顿下没有无条件时钟周期或显示deadline保证。

## 错误

失锁、bridge fault、无主/提前/未知响应、错ID、WLAST/RLAST错误粘滞锁止新请求。
已接纳/发布命令与W/B/R必须继续保持/按advertised长度排空，不能靠局部reset取消。
若桥已隔离或native不恢复，只能可信协调恢复；未假装busy=0可释放全局帧。
错误响应本身原样传送，合法AXI SLVERR/DECERR不是无条件改变现有错误策略的理由。
port_drained仅代表本调度器无已接纳事务，不证明其他master/像素缓存已退休。

## 验证

先用桥的写优先行为保存持续竞争下读不能获得服务的RED，再实现独立调度组件。
协议TB验证grant公平性、读优先配额、地址/响应背压、反序数据、最大长度计数、
错ID/LAST/提前/未知响应、失锁以及错误后保持排空。关键守卫变异必须被断言检出。

数字集成接真实ABI2采集端点、开启rearm的三分支核、raw_display、调度器、唯一
axi128_hmic256桥和字节内存模型。连续换图、轮换三槽；采新槽时继续扫描旧槽，
之后提交已采好槽，等待真实commit/release再复用旧槽。测试控制器保留CPU角色，
不把仿真槽资格检查误称为生产CPU库/显示MMIO退休适配器已经接入。
逐像素核验真实输出并独立检查所有三路写入、桥写后读回及同端口B后读；记录实际
重叠、等待、事务和欠载。测试仅所列几何/时钟/延迟模型，物理DDR和全尺寸带宽另验。

显式filelist、8ns组件综合与独立审查后交付。旧ABI1/2、显示及F4c2a生产字节保留。
