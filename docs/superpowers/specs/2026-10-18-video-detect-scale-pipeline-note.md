# 检测缩小组件算术流水补充

本补充沿用已批准的独立Video组件边界，不修改125MHz目标或对外数值/握手规则。原设计及计划71c3e68保留，作为实施前记录。

首版PDS组件综合`20261018T074541_300554Z`成功生成316 LUT、85寄存器、1 DRM，但SNR性能估计为89.6298MHz、8ns下WNS−3.157ns，224个内部setup端点有15个失败。最差路径是column_sums/DOA经累计/常数除法到output_rgb/D，16逻辑级。该版本只证明综合成功，不能称作125MHz可用；对应原全回归`20261018T074723_041506Z`已主动停止并记为superseded_incomplete，不能汇报为完整PASS。

单一修正是把算术分为三个寄存阶段：第5像素接纳时寄存三路sum+12，下一拍寄存常数5243的26bit乘积，再下一拍把各乘积[24:17]放入输出寄存器。两个pending位预留唯一输出槽，期间暂停输入；输出仍保持至ready，公开VALID不因fault撤销，clear/reset取消全部pending状态。RAM和乘积数据寄存器不复位，只在对应有效标记成立时读取。

对全部可达n=sum+12∈[12,6387]，有floor(n/25)=floor(n×5243/131072)。因为25×5243=131072+3，近似乘法较真实商增加3n/(25×131072)，上界小于0.006；真实分数部分最大24/25=0.96，不会跨越下一整数。商范围0..255，因此取乘积[24:17]正确。另已对更宽的n=0..6387逐值验证，正式RTL测试仍对sum=0..6375构造真实25像素逐帧核验，不用此乘数作为oracle。

输出比首版增加两拍，接口未约定固定零延迟。测试的最终输出保持场景改为等待4拍后检查，数学oracle和背压断言不变。该改动须重新定向回归、突变、综合及独立审查；综合估计通过也不等于布局布线时序或板测。
