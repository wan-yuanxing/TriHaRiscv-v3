# 800×600 原分辨率全屏与功能键切换设计

日期：2026-10-19。设计基线：`a984ec3`。状态：用户已确认方案方向；本批完成设计与规格修订，RTL、显示 MMIO、按键管脚和新板级验收尚未实施。

## 1. 目标与选型

正式 HDMI 输出固定 800×600、40 MHz，完整原图以 4:3 原分辨率铺满有效区。独立 MODE 功能键循环切换 RAW 原图、BOX 检测框、AVATAR 头像覆盖；KEY0 保留协调复位/重采用途。

| 方案 | 特点 | 决定 |
|---|---|---|
| raw 800×600 直接全屏 | 原始清晰度，检测/贴图直接使用原图坐标；显示读流量约为旧版四倍 | 正式方案 |
| preview 400×300 放大两倍 | 配合行/像素复用可保留较低 DDR 读取量，但丢失原始细节 | 不作为原分辨率验收目标 |
| 旧双窗 | 已有同帧 CRC、实体 KEY0 和图像验收基础 | 保留独立诊断目标，不加入正式模式循环 |

主规格在原 `docs/TriHaRiscv_SoC_Design_Spec_v0.6.md` 内按日期修订，避免现有引用与公共 `spec_version=0.6` 失配。模式变化不改变 HDMI 分辨率/同步/扫描率。当前 JSON 的 preview 几何和生成头仍描述既有实现，正式显示配置在实施阶段同源扩展。

## 2. 复用边界与文件组织

采集继续使用现有 `video_three_branch_capture`、raw/preview/input DMA 与写仲裁，三路完成语义沿用。三个 2 MiB 帧槽中 raw 偏移 0、stride 2400 B；preview 偏移 0x160000、stride 1200 B。

检测输入沿用外部 NPU `4fc0fc8` 的冻结契约：320×240 有效区、上下各 40 行零、UINT8 BGR NCHW、307200 B、预处理版本 1，各用 320 KiB 输入槽。

现有 `preview_display.sv` 是双窗组件；其 DMA/CDC/提交/释放机制可作依据，但不能仅将 PREVIEW_WIDTH 改为 800。窗口映射、bank 归还、首行时间、同槽控制更新都需要新行为和测试。

## 3. 像素路径与行缓存

```text
同帧 raw → 128bit 行 DMA → 双 bank/双时钟行 RAM
                                  ↓
                          RGB888 像素对齐
                                  ↓
                 RAW / BOX / AVATAR 像素流水
                                  ↓
                 RGB、DE、HS、VS 同步延迟
                                  ↓
                        40 MHz HDMI TX
```

有效区 `(0,0)..(799,599)` 一对一读取 raw，不缩放/裁切。每行 2400 B，即 150 个 128bit beat；每 bank 有效 2400 B，两 bank 共 4800 B，实际 DRM 按宽度/端口与综合报告确定。每次扫描读取 600 行，重复显示仍计 raw 读流量。

行读取按既有 AXI 子集拆分 INCR burst、最多 16 beat、4 KiB 边界及行尾。保留 R/G/B 递增字节顺序，验证跨 128bit 字边界的 RGB 拼接。扫描不能反压或停顿。

bank 生命周期为 FREE→FILLING→READY→CONSUMING→RETIRING→FREE。DMA 完成不代表 bank 可覆写，必须等待最后像素通过 RAM 与叠加流水；RAM 不依赖 reset 清零。

新帧首行与必要叠加资源在提交前就绪，后续行须在实际消费截止时间前预取完成。全屏从 `(0,0)` 即需图像，旧双窗顶部 150 行的准备时间不再存在。记录每行请求/就绪/消费/归还和最长等待，不仅测平均带宽。

## 4. 模式与按键

| 编码 | 名称 | 输出 |
|---:|---|---|
| 0 | RAW | 原图，关闭框与头像 |
| 1 | BOX | 原图＋最多 16 个 NMS 后框，五点独立使能 |
| 2 | AVATAR | 原图＋一张主人脸头像，默认关闭框 |
| 3 | 保留 | 拒绝，不修改活动状态 |

复位默认请求 RAW；首张图像未就绪时显示本地背景。最终验收须具备三个模式；分阶段只有 RAW 时发布实际能力，不将无叠加图像标作 BOX/AVATAR 已完成。

MODE 引脚经两级同步，稳定按下 20 ms 产生一次事件，稳定释放 20 ms 后才能再次触发；长按不连发，短抖动不触发。门槛由实际控制时钟参数计算。板级接入前以原理图核对并发布管脚/电平及约束，不猜用 KEY1；KEY0 继续协调复位/重采。

正式 SoC 由 CPU 驱动作为唯一控制所有者，消耗按键事件并生成请求；独立诊断用同接口本地控制器代替，两者由目标配置选择。按键不直接跨域修改像素选择器。

模式状态包含：`requested_mode` 最后合法请求，`request_seq` 请求序号，`active_mode/committed_seq` 实际提交状态，以及 `pending/unavailable/error`。序号与旧事件的隔离遵守系统协调复位协议。请求与实际状态都必须可观察。

等待期间多个按键按 RAW→BOX→AVATAR→RAW 累计，保留最后期望值，记录 request/commit/coalesced 计数；被合并中间请求不保证可见。在途提交 payload 保持稳定，新期望值在前次接纳后另行准备。

BOX/AVATAR 要求同帧有效检测结果，AVATAR 还要求素材与目标可用。缺少能力返回 unavailable，结果/预取未就绪则 pending，继续显示完整活动记录。有效无脸结果正常可提交，叠加为空；禁止借用旧帧结果。

## 5. 原子提交、CDC 与所有权

显示记录包含独立显示版本/能力、提交序号、slot/frame_id、raw 地址/stride/固定几何、同帧结果有效性、最多 16 框、主人脸/头像/素材参数、模式及模式序号。实施时从共同源发布显示 ABI；当前采帧 ABI1 没有此能力，本批不分配新偏移或改变既有字段。

core 接纳前检查地址/对齐/分配长度、slot/frame_id、模式能力、结果身份及素材边界。稳定记录经握手跨域，scalar 仅首级同步，bundle 按既有方案约束束路径；禁止全时钟组 false-path。复位跨域状态须协调，公开 AXI 事务仍需排空。

在首行和对应资源就绪后的安全帧边界，同时锁存 raw/同帧叠加/模式和序号。错过准备窗口就推迟，不能半帧切换或部分提交。事件保持至消费者接纳。

同一 frame_id/slot 的模式更新使用专用控制事务，要求 raw 地址/stride/几何与结果身份匹配；继续持有原槽，不重新走旧组件“受保护 base 不可新提交”的接纳路径。纯模式变化不释放槽，不清除 raw bank/FIFO，也不触发采帧、NPU、HDMI 初始化或 DDR 校准。若 raw 身份改变，必须走完整新帧记录。

新帧与新模式可在同边界合并为一个完整提交，记录模式序号及新 frame_id。旧槽须等所有 DMA、预取、行缓存和像素流水引用退出，才能 DISPLAY_RELEASE_ACK。MODE 提交通知不能充当释放确认，事件背压不能提前回收或覆盖记录。

正式应用的 RAW 也消费已经真实处理的帧；独立 raw 诊断可以不运行 NPU，但更新率须单独报告。

## 6. 坐标和叠加

显示坐标等于原图坐标。当前 NPU 连续几何坐标还原为：

```text
x_raw = 2.5 × x_net
y_raw = 2.5 × (y_net - 40)
x_display = x_raw
y_display = y_raw
```

网络有效区为 `[0,320)×[40,280)`。补边中心候选删除，跨界框裁剪。框为半开区间，左上 floor、右下 ceil，裁到 `[0,800)×[0,600)`，删除零面积框。像素缩小的采样/舍入与框几何转换分开；不加旧窗口或 ROI 偏移。

头像 RGBA8888 非预乘 Alpha，最近邻缩放；源坐标从未裁剪的目标矩形计算，只裁输出范围：

```text
out = floor((alpha × avatar + (255-alpha) × background + 127) / 255)
```

alpha0/255 精确返回背景/素材。目标可覆盖全屏，地址中间值须足够宽并检查素材范围；不沿用旧小窗限制规避边界。素材行预取/缓存独立追踪引用，按实际最大覆盖尺寸测压力。叠加直接在扫描流水完成，不生成额外处理后整帧。

## 7. 带宽与时序

```text
f_scan = 40000000/(1056×628) = 60.316541208... Hz
B_base = (1440000 + 360000 + 307200) × f_cap
         + 1440000 × f_scan
```

`f_cap=24` 基础约 137.428619 MB/s；采集也达到固定扫描率时约 213.954835 MB/s。此处保留 preview 写入，未计 NPU、CPU、头像、协议和刷新。全屏 raw 扫描约 86.855819 MB/s，活动像素期间消耗率 120 MB/s。

行周期 26.4 μs，800 个活动像素持续 20 μs。两 bank 只能覆盖有限等待，不能据平均流量或总线理论带宽承诺不欠载。共享 fabric 测最坏连续停顿和预取截止时间；组件综合、布线、外部 HDMI AC、实际板测分别验收。

主规格同步清理了关联的旧输入数值。另发现早期 NPU 原始输出每槽 64 KiB 草案不足以容纳 320 输入的 2100×16×2＝67200 B；输出 ABI 需 NPU/CPU 冻结后才用于正式整网。显示只消费有限后处理框，不自行调整模型或分配原始输出地址。

## 8. 故障与统计

无有效帧时显示本地背景。活动扫描欠载时以统一背景色填充受影响像素并锁存故障/计数，HS/VS/DE 持续；禁止用旧 bank 冒充新行。头像供数错误时该位置显示原图并锁存叠加故障，该扫描不作为健康叠加样本。AXI 错误/失锁按公开长度排空，再受控恢复。

非法模式/地址/版本或错帧参数在接纳前拒绝，活动记录继续显示；失效结果可保持上一完整画面并报告过期。初版 sticky 显示故障通过受控恢复清除，MODE 不清故障或撤销总线事务。

记录 DISPLAY_SUBMIT、DISPLAY_COMMIT、SHOW_FRAME_FIRST、MODE_REQUEST、MODE_COMMIT、DISPLAY_RELEASE_ACK，附 frame_id/slot/模式/序号；统计重复扫描、合并、unavailable、欠载和 DMA 错误。SHOW_FRAME_FIRST 在 RGB/DE 流水末端取样；去掉旧 3.96 ms 布局偏移后，仍测提交相位和流水延迟。

同一真实处理 frame_id 的效果切换不增加有效输出帧数，MODE 响应延迟另报。raw 诊断刷新与真实推理后有效输出 fps 分开记录。
