# CPU-only Pango resource measurement

执行用户已批准的下一阶段：单发射CPU-only原生综合、RAM/乘法器映射核对，再准备100MHz后布线。使用现有CPU工作树和Windows PDS，不修改固定核RTL、不集成SoC或编程板卡。

选择直接以`triha_core`为综合顶层，所有核接口保持为端口，使用PG2L100H/FBG676/-6和PDS ADS。相比综合整个测试TCM/SoC，此方式直接统计核；相比立刻构造物理测试夹具，此方式先发现不受支持的语法、资源映射和容量问题。单/双发射通过PDS顶层参数0/1比较，其余RTL、器件、100MHz时钟声明保持相同。

显式CPU-only清单包含生产核和头文件，不允许测试平台或TCM。每次构建把冻结源文件复制到独立build目录，核对原始来源哈希，保存工具版本、实际命令、生成Tcl、综合/映射报告及输入输出哈希。工具退出0之外，必须存在各阶段成功标记、可解析资源报告和完整核顶层。错误返回非零，禁止接受旧报告或在失败时留下PASS。

综合LUT/FF/DRM/APM按CPU核整体报告；映射网表另行统计实际原语，不能把综合前数组或`*`运算符当成已经映射的RAM/DSP。报告中的IO资源单独列出，不混入核逻辑面积。此目标不包含TCM/Cache/DDR/NPU/Video。

10ns时钟声明只用于综合目标，当前总线输入输出尚未绑定正式SoC时序。只有后续独立物理目标的实际Slow/Fast setup、hold、脉宽全部通过才能验收100MHz；本次综合估算不作频率结论。若映射产生不合适的资源或失败，先依据真实报告诊断，再决定窄适配与对应仿真，不盲目改写源代码。
