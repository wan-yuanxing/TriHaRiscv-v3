## 2. 主人脸选择与头像定位

CPU接收最多16个可显示的NMS保留框，要求坐标位于800×600原图内、宽高为正，并保持分数降序。主人脸在这组框中按面积最大、分数最高、候选序号最小的顺序选择。关键点掩码及五组关键点坐标保持零。

设主人脸框左上角为 `(x_b,y_b)`，宽高为 `w,h`，素材覆盖系数为 `q`，素材锚点为 `(a_x,a_y)`。与C实现完全一致的定位公式为：

\[
S=\left\lceil\frac{\max(w,h)q}{256}\right\rceil
\]

\[
c_x=x_b+\left\lfloor\frac{w}{2}\right\rfloor,\qquad
c_y=y_b+\left\lfloor\frac{h}{2}\right\rfloor
\]

\[
x_0=c_x-\left\lfloor\frac{Sa_x}{256}\right\rfloor,\qquad
y_0=c_y-\left\lfloor\frac{Sa_y}{256}\right\rfloor,\qquad
x_1=x_0+S,\quad y_1=y_0+S
\]

这里的整数中心与锚点偏移分别取整，不能合并成先做实数减法再统一取整。固定素材采用 `q=384`、`a_x=128`、`a_y=160`，即 `S=ceil(1.5 max(w,h))`，锚点偏移分别为 `floor(S/2)` 和 `floor(5S/8)`。软件接受的通用参数范围为 `0≤a_x,a_y≤256`、`1≤q≤1024`，不应把固定值写成所有素材的约束。

目标区域为左闭右开的正方形 `[x_0,x_1)×[y_0,y_1)`，端点按有符号16位写入记录。软件保留可能伸出屏幕的完整正方形；像素端只限制可见覆盖范围，不把目标矩形裁剪后重新拉伸。目标位置完全由当前主人脸框和固定锚点确定。

可用于正文：

## 3. 缩放与alpha混合

素材在DDR中为256×256、RGBA8888、每行1024 B、总计262,144 B，字节顺序为R、G、B、A，采用非预乘alpha。该格式与送入混合器的32位值 `R[31:24], G[23:16], B[15:8], A[7:0]` 对应。

对有效覆盖像素 `(x,y)`，采样坐标及相对字节地址为：

\[
u=\left\lfloor\frac{256(x-x_0)}{x_1-x_0}\right\rfloor,\qquad
v=\left\lfloor\frac{256(y-y_0)}{y_1-y_0}\right\rfloor,\qquad
\Delta A=4(256v+u)
\]

覆盖条件保证 `0≤u,v≤255`。`avatar_sample_map` 使用一级差值准备和八级二进制小数除法流水实现这一向下取整的最近邻映射，每拍可接收一个像素。这里不使用半像素中心修正，也不采用头像纹理双线性插值。输入预处理中的5:2双线性缩放是另一条数据路径，不能混写。

每个RGB通道按下式合成，`F`为素材通道，`B`为原图通道，`a`为8位alpha：

\[
C=\left\lfloor\frac{aF+(255-a)B+127}{255}\right\rfloor
\]

RTL先求 `s=aF+(255-a)B+127`，再以 `(s+1+(s>>8))>>8` 实现整数除255；`0≤s≤65152`。因此alpha为0时精确输出原图，为255时精确输出素材颜色，中间值按上述整数规则舍入。不是除256，也不是预乘alpha公式。

素材响应缺失或错误时，当前像素的前景与alpha均被置零，输出原图并置像素错误；`overlay_fault`保持错误状态。这一逐像素回退不代表整个应用能够在错误后自动继续提交新帧。

证据：`assets/avatars/triha/manifest.json:7-13`；`rtl/video/avatar_ddr_cache.sv:119-126`；`rtl/video/avatar_sample_map.sv:13-65`；`rtl/video/display_overlay.sv:43-51,130-175`。

可用于正文：

> Video将目标矩形内的原图坐标映射到256×256头像纹理，采用最近邻采样获得RGBA像素，再按8位alpha对素材与原图逐通道混合。坐标映射及混合均采用定点流水实现，RGB、同步信号和帧身份保持对应，合成结果直接输出至HDMI，无需将整帧合成图写回DDR。

## 4. 无损行区间缓存

行区间表为每个素材行记录紧凑存储起点 `base_y`、左端点 `L_y` 和不包含的右端点 `R_y`。生成器寻找该行所有**32位RGBA值非零**的像素，保留从最左至最右非零像素之间的完整连续区间；全零行使用空区间。

因此，区间内部的零像素仍被保存，alpha为零但RGB非零的像素也必须保存。这不是按alpha是否为零进行删减，不改变颜色或alpha位宽，也不对半透明边缘量化。

读取时，若 `L_v≤u<R_v`，片上地址为 `base_v+u-L_v`；否则返回完整的 `32'h00000000`。固定表保存34,331个RGBA字，即137,324 B像素载荷，为原始载荷的52.38495%，减少124,820 B。RTL将其分成32,768字的主存储和1,563字的尾存储；这些是逻辑像素容量，不能据此直接换算器件BRAM数量，也不包含区间表及控制状态的成本。

加载仍从DDR读取全部65,536个RGBA字，对全部262,144 B计算CRC。紧凑路径同时核对素材ID、素材代次及预期CRC，拒绝表外非零数据，并核对最终保存字数。最后一个逻辑字接收后，等待延后一拍的物理写入完成才置 `asset_ready`，避免写流水尚未结束就开放读取。像素域在就绪同步后锁存稳定的素材身份。

固定素材身份为 `asset_id=1`、`generation=2`、`CRC32=0xedc540a8`、基址 `0x82600000`。行区间表只适用于这份固定素材；更换素材必须同步更新身份、校验值与区间表，并通过共同复位后的装载流程。

证据：`scripts/video/gen_fixed_avatar.py:18-38`；`rtl/video/include/avatar_span_table.vh:1-5`；`rtl/video/avatar_texture_cache.sv:22-74,84-149`；`rtl/video/avatar_ddr_cache.sv:39-51,75-83,119-135`；`assets/avatars/triha/manifest.json:4-18,24-29`。

可用于正文：

## 5. 像素上下文环形存储

`display_overlay`使用16项、每项84位的环形RAM保存像素上下文，包含帧号32位、横纵坐标各11位、DE/HS/VS/SOF各1位、RGB 24位、框与点标志各1位，合计84位。存储逻辑容量为1,344 bit，即168 B。

写指针每个像素时钟加一，包含消隐时钟；同步读地址为 `(write_pointer-9) mod 16`。填充计数器及有效位在复位后遮蔽旧RAM数据，RAM本体不逐项清零。读写地址固定相差9，因此同拍不会访问同一项。

以 `display_overlay` 输入在时钟沿 `n` 被采样为基准：采样请求在 `n+8` 后形成，缓存于 `n+9` 读取并给出寄存响应，混合乘加在 `n+10` 使用对应上下文，除255修正在 `n+11` 完成，RGB、同步及标志在 `n+12` 后输出。这是该模块的13级阶段编号，不能写成整个HDMI链路只有13拍延迟。其上一级还具有RAW输入寄存及独立身份延迟。

在途数据的安全性由固定读写间隔保证：第 `n` 拍写入的RAM项在 `n+9` 被同步读取，`n+10` 已进入混合寄存器，直到 `n+16` 才会被环形写指针再次覆盖。该关系要求所有像素时钟连续推进，不能为某个模块单独增加停顿；现有通路没有反压，连消隐像素也按同一时序保存。复位使有效标记和填充计数归零，避免未填满时发布旧上下文。帧引用的释放另由提交、读取排空及流水退役协议约束，不能仅凭ring读出就释放原图槽。

环形RAM仅替代这组84位上下文的延迟存储。素材身份仍有9级64位标签，输出的代次、提交序号、槽号及模式仍有13级68位标签，不能声称全部像素元数据均已改为环形RAM。

证据：`rtl/video/display_overlay.sv:3-6,106-175`；`rtl/video/display_record_pixels_compact.sv:128-156,197-209,240-246`。

可用于正文：

> 为使纹理读取响应与原图像素严格对齐，合成通路以16项环形RAM保存像素颜色、坐标、同步信息及帧号，并通过固定间隔的同步读取提供混合上下文。复位后的填充计数屏蔽旧存储内容，后续流水同时传递像素身份和显示标志。

## 6. 读突发与4 KiB边界

原图读取和素材初始化读取均采用128位数据接口、16 B地址对齐、INCR突发，每个突发最多16拍。设当前地址为 `A`，尚需读取的完整数据拍数为 `N_rem`，本次拍数为：

\[
N=\min\left(N_{\mathrm{rem}},16,\frac{4096-(A\bmod4096)}{16}\right),\qquad ARLEN=N-1
\]

原图一行2400 B，即150拍，但不能写成每行固定10个突发。行起点随2400 B跨度变化，临近4 KiB边界时需要拆分；例如基址 `0x82000000` 的第1行（从0计）会在 `0x82000f60` 处先读取10拍至页末，再从 `0x82001000` 继续。对固定800×600布局作静态地址演算，507行需要10次突发，93行需要11次。

读仲裁器另外校验起始地址位于 `[0x80000000,0x88000000)`、`ARLEN<16`、`ARSIZE=4`、`ARBURST=INCR`及16 B对齐。由于单次最大256 B，只在页内最后256 B检查末拍不越界；逻辑条件为 `addr[11:8]!=0xf || addr[7:4]<=15-ARLEN`，与完整4 KiB边界判定等价。

仲裁器一次保持一个突发及其来源，响应按已锁存来源返回；`RID`用于核对，不用于临时决定响应去向。以上为设计和静态算术结论，不是带宽或硬件吞吐实测。

证据：`rtl/video/raw_display.sv:122-144,226-261`；`rtl/video/avatar_ddr_cache.sv:48-51,69-73,134-135`；`rtl/video/video_read_arbiter.sv:17-43,73-83`。

可用于正文：

> 显示读取按行组织为最多16拍的128位突发，并根据剩余数据量及当前4 KiB页内空间调整突发长度。读仲裁器在接收请求时检查地址、拍长和页边界，锁存事务来源直至响应结束，保持原图与素材读取的请求、响应对应关系。

## 7. 显示记录压缩与外部640 B ABI

外部软件接口保持160个32位字，共640 B：32字头部加16组、每组8字的检测框记录。MMIO基址为 `0x20011000`，影子记录偏移为 `0x100`，ABI版本为 `0x00010000`。软件仍写入完整160字，随后写模式、提交序号，经fence后写SUBMIT。头像身份、基址、尺寸及目标矩形保存在头部第14至22字。

在本板级 `ENABLE_LANDMARKS=0 && SKIP_GUARD=0` 条件下，内部准备记录只保留32字头部和16组矩形的各2字坐标，共64字、2048位；另有每框1位、共16位的非法载荷标志。每框余下6字在合法记录中均为零。非零或未知的禁用字段会折叠进标志并交给校验器拒绝，不能被静默丢弃后当作合法记录。

影子RAM和活动历史RAM仍各有160×32位。影子记录的字节写使能与读回范围保持完整；仅模式更新通过逐字比较全部160字确认内容不变，不用哈希代替比较。记录准备采用FETCH/LOAD两拍处理一字，160字需要320个准备时钟，后面还有校验及提交过程，不应把320拍写成端到端提交延迟。

内部描述符在向下游提供时重新展开成5120位逻辑总线。该总线及“记录位宽5120”不代表软件ABI缩小，2048位准备记录也不代表整个显示子系统只保留一份256 B记录。跨域握手只复制控制身份，源记录保持稳定直到实际提交反馈；像素端在匹配原图身份且素材身份有效的SOF处锁存记录，并等待首个合成像素完成流水后返回提交反馈。

证据：`sw/include/video_display_abi.h:4-14,49-76`；`sw/drivers/video_display.c:6-31`；`rtl/video/video_display_mmio_compact.sv:36-46,144-205,303-337,345-356`；`rtl/video/display_record_guard.sv:26-36,55-83`；`rtl/video/display_mode_cdc_held.sv:3-9,45-72,84-95`；`rtl/video/display_record_pixels_compact.sv:118-169`。

## 8. 三种模式、按键及无脸结果

| 模式编码 | 完整头像应用的实际行为 |
| --- | --- |
| 0 / RAW | 输出已提交检测帧的原图，不绘制框或头像；采集、推理和帧调度继续执行 |
| 1 / BOX | 绘制有效掩码中的全部保留框，普通框为绿色、主人脸框为红色，边框在矩形内部宽2像素 |
| 2 / AVATAR | 对主人脸对应的头像目标区域进行RGBA合成；该分支不同时绘制BOX边框 |

无脸结果由软件初始化为 `RESULT_VALID|RESULT_EMPTY`，不设置框掩码、主框或头像启用信息。三种模式均保持该帧原图，不沿用上一帧的头像。RAW模式仍展示同一帧池中的已处理帧，并非绕过推理的直接输入视频旁路。

KEY1接入C23，低电平有效，经双级同步和20 ms稳定判定产生单次按下脉冲；125 MHz配置下对应2,500,000个时钟。长按不会连续切换，稳定释放后才能形成下一次按下事件。请求模式从0复位，按 `RAW→BOX→AVATAR→RAW` 循环。

固件检测MODE_KEY能力后轮询 `MODE_REQUEST`，由CPU执行正常显示提交。若存在待显示完成帧，选择最早就绪帧；若没有新帧但已有活动帧且模式不同，则对该活动帧进行仅模式更新。按键只改变请求，实际显示在后续匹配SOF和提交反馈后生效，不能表述为按下后立刻异步切换像素。

`main.c`中启动时自动选择BOX的分支仅在没有MODE_KEY能力时执行；完整头像配置存在该能力，初始模式为RAW。这正是现有正文与该应用的主要差异之一。

## 9. 封存、错误保持与复位

完整头像配置在六个模型相关段之后装载第七段固定RGBA素材。装载器检查包CRC、段序号、偏移和完整段CRC，等待对应写响应成功；第七段最后一次写响应完成后才置 `model_sealed_o`。包CRC或顺序错误可以返回错误状态供主机重试，不宜把所有通信校验失败一概描述成必须复位。

封存后，SoC只发出一次固定素材加载请求。`avatar_ddr_cache`再次读取完整素材并计算CRC，在最终CRC通过前不发出最后一个缓存字；纹理缓存再等待最后物理写入完成才发布就绪。故“模型装载封存”和“片上素材可供像素读取”是两个顺序相接的条件，不能视作同一个时刻。带头像的非空记录会等待素材就绪并核对素材身份，像素端应用记录时再次核对。

纹理缓存在就绪后不再接受新加载，同一运行阶段保持内容不变。素材退出某一帧的显示引用不等于允许覆盖缓存；本配置没有运行中替换素材的流程。这里描述的是装载器、缓存及应用的更新约束，不应扩大为对所有DDR访问方实施了全局写保护。

KEY0为低有效 `rst_in`，接入C22。板级应用复位由控制器启动复位与计算PLL锁定共同限定，各时钟域分别同步释放；计算PLL失锁会使应用进入共同复位，DDR PHY的复位仍由独立启动序列控制。共同复位清除模式请求、模型封存、素材就绪、显示握手及应用状态；重新运行需要重新装载。运行中的锁存故障不等于自动执行复位或热替换：固件保存错误后停驻，保留帧引用。

须区分三类身份：帧号用于槽复用；帧记录的generation取自会话epoch；素材generation标识固定素材版本。本板级源码把epoch固定接为1，素材generation固定为2，**没有实现每次复位自动递增epoch**。复位隔离依靠各相关域及状态共同清除，不能从字段名称推导出跨复位单调计数能力。
