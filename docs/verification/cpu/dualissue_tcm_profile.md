# 双发射 TCM 性能诊断（2026-10-23）

用户确认以片上 SRAM/TCM 的最高性能作为超过 4 CoreMark/MHz 的主目标。
DDR Cache 开关结果独立列于 [测试矩阵](dualissue_cache_matrix.md)。

使用同一 GCC15.2 -O2 固件，五次 CoreMark 的 RTL 短测：

| 配置 | 周期 | CoreMark/MHz |
|---|---:|---:|
| 双发射基线 | 1,411,226 | 3.543019 |
| 窄乘法结果提前转发诊断 | 1,366,766 | 3.658271 |

候选减少 44,460 周期，吞吐提高 3.252934%。超过 4 尚需再减少至少
116,767 周期。此结果不是官方分数或板测；实际后布线 100MHz 和 CPU-only
资源尚未验证，生产 RTL 未应用此候选。

候选仅改变 issue 中两个生产者槽的窄 MUL 可用性判断与转发值选择，
复用既有乘法器 early-valid。保留宽乘法等待、同包 MUL 依赖阻塞及原优先级。
可复现变更保存在 [诊断补丁](dualissue_narrow_mul_diagnostic.patch)。

验证：基线定向测试按预期失败，候选 1061 检查通过；破坏乘法部分积负例
按预期失败。两组种子的 single/dual 有序执行检查通过，中断自检通过。
中断模式未进行 golden/candidate 精确轨迹比较。

基线/候选完整计时窗口的 1,448,448 个 WB 和 70,839 个 store 事件比较通过，
仅归一化经验证的第一次 cycle CSR 绝对时间及对应 started 存储。
WB 是观察计数，不能替代架构 minstret。两次 profile 的冻结源/输出哈希及
最终定向回归的当前输入/输出哈希均已核对；绑定见 [JSON](dualissue_tcm_profile.json)。

剩余测得瓶颈：130,544 个依赖阻塞周期、91,904 个前端等待周期；
520,727 次无第二条可用指令、120,156 次配对结构限制、199,299 次配对依赖拒绝。
后三者是已发射 A 的周期内分类，不能直接与停顿相加或当作可节省周期。
下一步优先分解取指包边界及真实依赖；跨包配对涉及 PC、异常和 flush 元数据，
需先建立定向失败测试，不能只放开发射条件。
