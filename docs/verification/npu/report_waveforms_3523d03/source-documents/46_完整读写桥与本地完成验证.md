# 完整读写桥与本地完成验证

版本：v1.0（单burst桥功能验证）；日期：2026-10-22。所属：2.3 控制/存储接口与 2.6 独立部署验证，作为下一版综合自检的开发输入。

## 1. 本轮范围

复用文档44/45已冻结的写桥、原生RX预留器、双时钟FIFO和四相mailbox，增加`npu_read_bridge`及单在途`npu_mem_bridge`。先验证100MHz本地完成语义、取消、安全排空、完成背压及所有权，再接实际生成的HMIC 1.10与两个x16 DDR3模型。地址仍为可重定位窗口内相对偏移，不分配系统物理基址。

## 2. 读侧契约

命令锁存offset、1..16拍、ID、epoch、client以及内部单调tag。非法长度、非32B对齐、超过1GiB或跨4KiB的命令本地返回状态1，不向原生口提交。命令、取消、原生完成各用独立mailbox；RX数据走UI到compute的真实32拍FIFO。

原生完成包含tag、状态和实际捕获拍数；它仅表示捕获结束。本地DONE必须同时满足匹配的原生完成已收到、实际FIFO消费/丢弃数等于捕获数，且无身份/计数/帧尾错误。成功必须捕获并消费N拍。取消可在AR前返回0拍，或在AR提出后完成N拍；本地取消已经记录而原生先返回成功时，本地返回7。状态8表示原生故障；身份/计数错误要求全会话复位，不伪造成功完成。

ABORT是一次请求，命令发送和已提出AR保持到握手。尚未对外提出的读数据可自动丢弃；已经VALID且被READY阻塞的当前拍必须保持数据和LAST，待调用方接收这一拍后再自动丢弃其余拍。因此调用方取消后仍应接收已经提出的一拍；若停止接收，只能由监督器进行完整会话复位。消费超时提出复位请求，不撤销已提出数据。读数据在DONE成功前均为推测结果，不能据此提前发布任务成功。

DONE的状态及ID/epoch/client在背压期间保持不变。所有权到DONE与READY握手后才释放。内部tag不回绕；最后FFFFFFFF任务退休后请求全会话复位。

## 3. 统一读写仲裁

统一命令增加write方向位，一个时刻仅接收一个burst。选定的读/写包装器拥有整个本地事务，包括数据、原生传输、取消和DONE背压。原生写返回而本地DONE未确认、读数据尚未取完或DONE未确认时，均不能接受另一个方向命令。采用现有原生AW/W及AR/R语义，不套用标准AXI的WVALID/BRESP/RREADY。

整会话故障禁止新命令，但不门控已经提出的原生AW/AR或已提供的本地读数据。外部复位必须覆盖HMIC、两个方向FIFO及全部mailbox/本地状态；本轮包装器本身不代替27MHz监督器。

## 4. 验证出口与边界

组合代理仿真需覆盖：1..16拍、逐字节/掩码回读、同ID多burst、读写切换、读本地背压、DONE背压、命令字段锁存、中止前/后AR、被阻塞读拍的取消保持、旧tag取消隔离、非法命令、原生元数据/超时/失校准、在途全会话复位及tag耗尽。至少沿用文档44的六组时钟/相位。

实际HMIC仿真须直接由新完整桥驱动，包含跨异步时钟的写入/读回、短/长burst、掩码和4KiB边界两侧。保留原始日志/VCD、来源SHA及真实波形图。实际模型的加速初始化、已有警告和有限测试范围单独说明；不据此签核板级时序、跨master fence、物理CDC、完整综合版位流或30fps。

## 5. 实现与接入方式

| 文件 | 责任 |
|---|---|
| `rtl/platform/npu_read_bridge.v` | 读命令69bit、完成41bit、取消32bit mailbox；真实RX FIFO；合并捕获/消费计数与保持DONE |
| `rtl/platform/npu_mem_bridge.v` | 统一方向位、单burst所有权；连接已冻结写桥与新增读桥，不增加数据缓冲副本 |
| `Testbench/platform/mem_bridge_driver.svh` | 代理/真实HMIC共用逐字节scoreboard、命令字段扰动、读/完成背压与所有权检查 |
| `Testbench/platform/tb_npu_mem_bridge.sv` | 可控原生代理、六时钟矩阵、取消/故障/整会话复位/tag上限 |
| `Testbench/platform/tb_read_completion_order.sv` | 延迟完成mailbox以测试数据先完成，及晚取消/已提出DONE的稳定性 |
| `Testbench/platform/tb_mem_bridge_hmic.sv` | 直接连接新增完整桥、实际HMIC和两颗x16 DDR3模型；不是旧BIST旁路 |

读桥状态顺序为IDLE→POST→ACTIVE→DONE→IDLE。非法命令从IDLE直接进入DONE；不使用脉冲完成。POST期间命令mailbox字段保持，ACTIVE收到原生完成后仍可等待本地数据交付。包装器身份/计数故障保持隔离请求，禁止新命令，直到外部完整复位。

| 接口/参数 | 定义 |
|---|---|
| `cmd_valid/ready`, `cmd_write` | compute域握手，write=1写、0读；接受后调用方可更改输入字段 |
| `cmd_offset/beats/id/epoch/client` | 32B对齐相对偏移、1..16拍、32bit ID、32bit epoch、3bit client |
| `write_valid/ready/data/strb/last` | compute域写数据，256bit/32bit字节掩码；复用文档42的完整包检查 |
| `read_valid/ready/data/last` | compute域读数据，256bit；取消后仍接收已提出的一拍；收到成功DONE前不发布有效结果 |
| `done_valid/ready/status/id/epoch/client` | compute域本地burst完成及身份；不是整帧/整任务完成或跨master fence |
| `busy/owner_write` | 到本地完成ACK才释放；DONE背压时另一方向也不能接收新命令 |
| `session_reset_req` / `ui_session_reset_req` | 各自域故障/隔离请求，外部监督器负责完整HMIC/FIFO/mailbox会话复位 |
| `COLLECT_STALL_LIMIT` | 写收集器无进度上限，默认1000000个compute周期，约10ms |
| `NATIVE_STALL_LIMIT` | 原生传输无进度上限，默认1000000个UI周期，约8ms |
| `LOCAL_STALL_LIMIT` | 读POST/ACTIVE无进度上限，默认1000000个compute周期，约10ms；0关闭该计时 |

内部tag在每次本地命令接受时分配，外部同ID/epoch/client可连续复用。取消只针对本次内部tag；晚到的旧取消不能影响下次同ID事务。tag到FFFFFFFF后拒绝后续命令，当前事务结束并被确认后请求会话复位。没有把内部tag复位/耗尽当作系统任务epoch协议的替代。

TX/RX两个FIFO合计沿用8 DRM36K等效的既有逻辑容量；新增mailbox/控制寄存器的实际资源与路径必须由完整PDS重新给出，不能从局部FIFO报告外推整体资源或时序。

## 6. 实际代理验证结果

正式目录为`build/platform/mem_bridge_v1_final`和`build/platform/read_completion_order_v1_final`。首轮两个`_01`目录为nominal探索运行，均通过；不计入正式矩阵。正式13个代理job的所有编译/运行汇总均为Errors=0、Warnings=0，使用实际GTP_GRS/GTP_DRM18K_E1及既有真实FIFO。

| 正式组 | job | 场景/本地burst数 | 逐字节比较 |
|---|---:|---:|---:|
| 完整桥六组时钟 | 6 | 558（每组93） | 86,592 |
| 读tag上限 | 1 | 2（写入准备+FFFFFFFF读任务） | 512 |
| 读完成先后次序/取消六组时钟 | 6 | 36（每组6） | 12,480 |
| 代理合计 | 13 | 596 | 99,584 |

时钟矩阵的compute/UI半周期及UI初始相位（ns）为`5/4/0.37`、`4/5/1.13`、`5.003/3.997/2.21`、`5/10.007/0.63`、`9.997/4/3.17`、`5/5/0`。这是功能压力矩阵；生产CPU/NPU仍为同根100MHz，UI125MHz，未改变目标频率。

主矩阵每组93场景由77个基础场景（含5个本地非法命令）、3个取消、11个故障以及2个在途整会话复位组成。覆盖1..16拍全写/交替字节掩码写与读回；偏移4064/4096两侧与1GiB最后32B；命令接收后扰动所有输入字段；同外部ID/epoch/client反复使用；DONE背压期间尝试另一方向，检查所有权不早退。

取消覆盖预留不足、AR已提出等待握手、已经提出的读拍被阻塞。故障覆盖RID、RLAST、AR无进度、返回无进度、失校准、错误完成tag/count/status、消费者不接收已提出读拍导致本地超时、FIFO接收不可用以及空闲时意外RVALID。可证明退休的原生故障返回8并隔离；无法证明身份/计数或捕获完整性时不产生伪DONE，而是请求完整会话复位。故障复位的模型同时清除原生代理在途状态，不能只清FIFO。

主矩阵每组有451拍本地实际接收、14,432次字节比较；原生RVALID观察计数会因故障/复位时的尾部相位而变化，不能把这些拍全算作成功交付。完成/数据保持与所有权检查为持续监视器，发现VALID撤回、字段变化或提前放行即失败。

补充矩阵每组含：写入准备、数据先取完而完成mailbox仍未接受、取完后完成前取消、DONE已提出后取消、部分返回时取消并延迟后续数据、最后同ID正常读回。每组6场景/2,080字节；明确验证“捕获先完成”和“本地先完成”两个方向。取消已经提出的一拍后安全丢弃尾部，不能要求调用方停止READY同时仍自动报告成功。
