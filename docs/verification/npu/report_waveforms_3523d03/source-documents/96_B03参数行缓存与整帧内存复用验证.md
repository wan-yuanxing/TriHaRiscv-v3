# B03 参数行缓存与整帧内存复用验证

2026-10-28，v0.1。承接[[93_B03完整程序整合与持续开发规格]]、[[94_B03完整层执行器与输出行缓存补充规格]]及[[95_B03完整帧执行与私有结果头规格]]。本页记录输入路径、普通内存相位复用和独立性能优化的实际仿真证据；完整79op、POST、真实HMIC和最终PDS结果分别归档，不由单元结果替代。

## 1. 输入路径正式 v1

`rtl/platform/b03_model_input.v` 提供三个串行命令：PARAMS、LOAD_ROWS、BUILD_A。所有任务在接受时锁存128B已解析op、地址、epoch、tag和几何；外部DDR输入直接按 `resolved_src_base` 读取。CPU不复制像素、不预展开卷积输入。

参数通过本地32B块服务读取，直接写4bank B权重cache及64Co bias/M/shift shadow。B每行16Co，地址为`co_block*K+k`。真实模型最大4864B参数slot由4096B权重、256B bias及512B M/shift组成，不塞进旧2560B参数控制镜像。检查权重−128、Co尾非零、slot零填、M在1..U31、shift在1..62，以及`255或127×sumabs(W)+abs(bias)≤I32MAX`。Add的96bit triple与Sigmoid的64bit pair按word22 aux0偏移读取，允许向32B扩读，不能对非空间1600元素错误套用Cin≤64。

ROI为16个1024×32真实E1 bank。channel mod16选择bank，group=channel/16；原版地址为`(group*3+ky)*ceil(Win/4)+x/4`。两个端口每CE写8B，支持最满64ch×3×320、每bank960word。Dense按K构造一次16M向量写4bank A，再对所有Co块复用。DW直接读16bank形成16个不同Co的activation。输入支持U8/S8，垂直/水平padding、Co尾及M尾为0；支持Pool与Resize的行读取。

A/B/DW接口均采用统一CE，真实请求寄存器和E1读边界；可每CE接受一条、两包含沿返回。无rsp_ready，父必须以同一CE暂停整个数据/valid/tag流水。本地memory req/W/R/rsp和done握手使用普通时钟。取消不能撤销已提出req，已接受事务必须排空；服务身份错误要求整个session reset。

正式报告：`build/platform/b03_model_input_v1/b03_model_input_validation_v1.json`，SHA256 `4969a28e9a485027caaa5c731b722bd14a279c9824691b1064c1995a55c8ff0f`。20组case，48个真实GTP_DRM18K_E1实例，244个A、508个B、12130个DW向量读回，655个service命令，3485个R beat，其中552个在CE=0退休。64条连续A/B与64条连续DW请求均实际通过。10种参数负例、epoch失效、held done、held cancel offer及错误service tag均通过，ModelSim compile/runtime均0 error、0 warning。外部块服务为字节代理，此报告不证明真实DDR或完整网络。

## 2. 普通内存相位复用正式 v1

`rtl/platform/b03_phase_mem_mux.v`让D(blockDMA)与P(冻结POST memory engine)使用唯一受监督桥。空闲时由`select_post`选择，捕获descriptor后直到完整DATA、匹配DONE及本地DONE ACK完成均不换owner。两个caller可各从local ID=1开始；mux为每个物理CMD分配独立递增32bit global ID，响应验证global identity后回送原local ID/epoch/client。FFFFFFFF可用一次，耗尽后隔离，不回绕。

CMD offer寄存，取消、bridge fault、client abort或epoch变化都不撤销已提出的普通valid。W/R只直接背压，不增加DDR数据缓冲；DONE仅保存一条metadata。最后DATA与DONE同沿按更新后计数检查。错误DONE身份、错误status、提前/重复DONE、错误last、额外R/W、非法地址/长度/页边界、timeout、source改写held CMD均锁quarantine和首次176bit CPAY。错误不释放owner；整个session reset才能重建。已暴露的held R/W/DONE即使发生后续fault仍保持原tuple，避免撤回普通握手。

正式报告：`build/platform/b03_phase_mem_mux_v1/b03_phase_mem_mux_validation_v1.json`，SHA256 `3f70675e894687c6a9a4c34455207233d07c29f414d58cff0a9898adb050f66b`。60case=33正常+27 fault；49物理CMD、155W/155R beat，34次DATA与DONE同沿。实际稳定性检查包含1206个held CMD、316个held W、267个held R和212个held DONE周期；compile/runtime 0 error、0 warning。桥backend是普通握手代理，没有把它报告为真实HMIC。

![正式相位复用普通握手与取消波形](仿真截图/b03_input_phase_v1/02_actual_phase_mux_wave.png)

下图包含rst_n，隔离后只有完整session reset才清除quarantine。正常DONE允许在本地ready=0时保存，不能因父相位变化丢失。运行入口为`jiaoben/zgtc/run_b03_phase_mem_mux_checks.ps1`。

## 3. 新 fast 输入路径 v1

原输入v1与其正式证据保持不改。`rtl/platform/b03_model_input_fast.v`采用相同接口，分别优化两处：最终ROI响应到达即进入A_WRITE；A_WRITE后直接准备下一K，最后K才等待A写pipeline排空。不同bank的A写与下一K准备重叠，仍仅一个gather上下文，不能称为多个K同时在途的完整gather流水。

三行cache对同op、同explicit源地址、同epoch且输出y恰为前一行+1的Kh3卷积启用ring。stride1复用旧2行，stride2复用旧1行；仅改变三个逻辑ky到物理slot的映射，不搬RAM行。倒退/跳行、op/源/epoch变更或上次rows无效均回到cold加载。padding的present位随逻辑行映射，不能读取旧RAM残留。

正式报告：`build/platform/b03_model_input_fast_v1/b03_model_input_fast_validation_v1.json`。21case、10次rolling、8次cold reload；48真实E1；A1135/B634/DW49030个向量，1688命令、8086个R beat，1329个CE=0 R beat。准确检查每次rolling的外部读取字节数，并通过stride1/2三次环绕、S8、64×3×320最满cache的底部padding、反向y和重绑定。参数负例、取消、错误tag、CE冻结及II=1与原版一致通过，0 error、0 warning。

| 相同输入命令 | 原版实测cycle | fast实测cycle | 条件 |
| --- | ---: | ---: | --- |
| 首层K27 BUILD_A | 277 | 195 | top-left，含TB固定CE暂停 |
| Cin64 K64 BUILD_A | 759 | 533 | Dense1×1，同输入tile |

这些是单元仿真命令周期，不能合成为整网30fps结论。固定TB暂停和服务背压会使不同独立命令的周期略有变化。完整网络仍需用新的fast层组合、真实九头和最终框复核。

## 4. 完整网络瓶颈与真实HMIC分级

对正在运行的旧完整网络实际VCD，`yunet/python/profile_b03_layer_vcd.py`按每个posedge解析layer stage。前16个已完整层的prefix归档在`build/platform/b03_performance_profile_dev01/partial_layers.json`，含prefix SHA与采样说明。起止各带额外边界采样，单层采样数较leaf cycle寄存器多2，不能把差异隐藏。首层895881周期中，AWAIT约62.1%、ROWWAIT约12.4%、STOREWAIT约10.3%；DW的ROW阶段可超过50%。原版全网后续实测由完整模型报告记录，单元fast版尚不表示满足33.33ms预算。

下一优化候选是在现16bank可容纳整feature时一次连续NCHW读取并驻留；不能通过新增DDR输入复制或PC预展开代替硬件搬运。多行output tile、DW输出快照和整网控制由对应层模块另行验证。

完整frame+blockDMA+phase mux+唯一受监督桥+实际生成HMIC+两x16 DDR3已实际compile 0E0W，并启动冷仿真。`b03_full_frame_hmic_dev01`在初始化阶段按协调决策停止；原始process/console/failure保留，手动停止产生的lost connection Fatal属于该停止结果，此目录不记PASS。旧实际HMIC正式作业33211个compute clocks耗2298.7秒，直接仿真完整千万级周期需要数天，故它不作为本轮完整程序可用的阻塞测试，也不以代理冒充物理整帧。

新增有界真实HMIC冷测试`tb_b03_small_model_hmic`使用Dense3Cin/1Co/4×4/s2→2×2，以及DW1Co/4×4→4×4，共20个有效输出byte与44个guard byte；HOST正常通过同一块服务装载约2KB参数/输入并读回，layer实际执行、真实DDR结果再读回比对。采用1fs和限定层级访问，不预装golden头。实际两层均通过：Dense1852cycle/54个MAC向量/2输出行，DW1223cycle/144个MAC向量/4输出行；67个物理CMD与DONE全部平衡，12个CE=0 R beat、10个CE=0 DONE，整个冷会话无恢复。真实仿真结束106686ns，host耗时约13.7分钟。原始目录为`build/platform/b03_small_model_hmic_dev01`。

该作业HDL exit0、runtime 0ERROR；原后处理复用了旧TB硬编码parser和旧文本校准事件，因缺少它要求的名字/事件而把84条既有DDR初始化WARNING判为unclassified，保留其原失败输出。独立`review_b03_small_model_hmic.py`重新审计同一原始console/transcript/VCD及编译快照，只接受两个真实chip实例、精确旧消息，且warning发生在本次实际`init_done`上升前：warning在12～27us，VCD上升在63.73728125us；267条静态厂商port-model warning仍按既有签名判定，任意ERROR或初始化后同类warning仍失败。独立审计结果`build/platform/b03_small_model_hmic_review_v1/b03_small_model_hmic_review_v1.json` SHA256 `c89fb09de299fdaf6416633d7414979ddd1b41fa66dd52a3f7f7c54a0962a41f`为PASS。原失败parser报告、原始日志与84条消息均未覆盖，`strict_DDR_timing_passed=false`保持。

## 5. Resident 输入与跨K流水正式 v1

按[[98_B03流水gather与驻留缓存优化规格]]新增`b03_model_input_resident.v`，保留原输入v1与fast v1。满足`ceil(Cin/16)*Hin*ceil(Win/4)≤1024`时仍用同16bank，布局为`(group*Hin+iy)*rowwords+xword`。首次LOAD_ROWS从explicit源地址按连续NCHW burst装入，64B FF skid按实际byte计数拼接跨beat数据，最多两个32bit word/CE写E1，行尾byte mask与channel plane边界分别推进；不新增RAM或DDR中转。后续同layer的LOAD_ROWS只计算3个逻辑ky的physical word offset及present，实际2cycle、0 DDR读取。无法整feature驻留时保留三行ring。

PARAMS无条件失效rows_valid/a_valid/resident_valid，明确建立新layer生命周期。即使同op、同地址、同epoch、同tag且host在两次layer间改变输入内容，新PARAMS之后也必须cold重读，不能跨层/跨帧复用旧像素。七组Dense/DW/Pool/Resize更改输入内容后实际重载并以新的源byte重新核验；取消在途gather后同样失效，不保留A/ROI成功标记。

BUILD_A接入独立`b03_gather_pipeline.v`，每K按需要的连续dword每CE双读，不插跨K准备/排空泡；K奇偶各一个288bit返回context，最后一组真RAM返回与context同沿组成128bit A写入。三条row_offset及group_stride适配ring与resident布局。helper完成后父仅等待最终A真实写pipeline排空一次。接入初次暴露了“常参function读取模块global数组不能可靠触发连续赋值重算”的仿真敏感性问题，已将CSR三offset显式依赖row_slot/resident_yword/row_win；失败日志保留，正式结果使用修正源。
