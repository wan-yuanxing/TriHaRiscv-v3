## 1. 修订内容与范围

### 1.1 本次已经确定的需求

| 项目 | v0.6 当前决定 |
|---|---|
| 视频输入 | 一路 HDMI，800×600 @ 60 Hz，非加密视频 |
| 视频输出 | **一路 HDMI，800×600 @ 60 Hz，完整 4:3 原分辨率全屏显示** |
| 检测范围 | 完整输入画面；删除固定 ROI 裁剪，不限定人脸必须出现在某个方框中 |
| 显示模式 | RAW 原图、BOX 检测框、AVATAR 头像；独立功能键循环切换，启动默认 RAW |
| 同帧叠加 | 检测框/五点/主人脸及头像参数与所显示原图使用同一 frame_id；同一已处理帧可切换效果 |
| 模型 | YuNet 为当前人脸检测部署基线；先保留预训练网络，不另设计新检测器 |
| 表情识别 | 当前不执行，只保留后续裁脸、模型调度和头像编号接口 |
| AI 推理 | 三种效果复用同一次检测结果；切换效果不重新采帧或运行模型 |
| 当前性能方向 | **有效输出帧率作为优化目标，争取 ≥24 fps，在保持检测效果、同帧对应和稳定性的前提下越高越好；30 fps 不作强制要求，也不设为软件限速上限** |
| CPU | 直接以六级单发射作为当前仿真、综合、上板与集成目标 |
| 工作阶段 | 阶段 0：平台验证；阶段 1：完整演示；阶段 2：性能优化 |

“人脸检测”指定位画面中的人脸，不进行身份识别。“头像替换”指预设素材的二维缩放和透明叠加，不是生成式卡通化、输入人物分割或背景修复。

### 1.2 当前不纳入的功能

不开发第二个物理 HDMI 输出、像素级人脸/人体分割、全身角色替换、任意旋转或三维形变、身份库、表情分类网络、复杂多人跟踪、通用深度学习编译器、硬件图级命令队列、CPU 双发射、乱序执行、Linux、MMU、浮点或向量单元。

本文只记录本次固定的视频输入输出模式，不列其他视频模式作为备选实施项。模型输入张量尺寸和显示窗口尺寸不属于 HDMI 输入模式。

### 1.3 全屏显示默认设计

以下是已选定的工程设计，实际资源、时序和板测另行验收：

| 事项 | 默认方案 | 必须确认的边界 |
|---|---|---|
| 显示区域 | 原图 800×600 RGB888 直接对应输出 `(0,0)..(799,599)` | 保持 4:3；不裁切、不拉伸、不由 400×300 放大代替原分辨率 |
| 效果模式 | `0=RAW`、`1=BOX`、`2=AVATAR`；`3` 保留且拒绝 | 原图/检测框/单主人脸头像，默认 RAW |
| 功能键 | MODE 稳定按下/释放各 20 ms，一次按下只产生一次循环请求 | KEY0 保留协调复位/重采；MODE 管脚由板级接入核对原理图后发布 |
| 生效点 | 图像与叠加参数、frame_id、模式在安全输出帧边界原子提交 | 请求/接纳/实际提交分别记录；准备不充分则延后 |
| 显示读取 | 从 raw 平面按行预取，双 bank 行缓存，每行 800 RGB 像素 | 每 bank 有效 2400 B；最后像素及在途引用退休后才能覆写 |
| 兼容采集 | 当前 raw/400×300 preview/320×320 input 三分支继续生成 | preview 留作诊断及兼容；去除须另行修订完成事件/ABI |
| 检测输入 | 800×600→320×240 双线性，上下各补 40 行，UINT8 BGR NCHW | 沿用外部 NPU 固定提交 4fc0fc8、输入版本 1；见第 6.3、8.2 节 |
| 帧存储 | 三个 2 MiB 帧槽；原图及原 preview 偏移沿用现有分配 | 检测输入独立 320 KiB/槽，正式共享可见性及所有权另验 |
| 主人脸 | 有效检测中优先面积最大者；并列按分数与候选顺序确定 | 首版不做身份连续性或跨帧滤波 |
| 贴图 | RGBA8888、最近邻缩放、平移、非预乘 Alpha 混合 | 按原图坐标裁剪并逐像素验证 |

现有双窗诊断入口和验收证据继续作为历史基线；正式运行不把双窗加入 MODE 循环。

### 1.4 v0.6 性能要求修订

2026-10-14 的 v0.6 修订调整了性能目标。2026-10-19 进一步将正式显示由双窗改为全屏效果切换；固定 HDMI 时序、真实推理要求、三帧槽和三路线并行安排沿用。

2026-10-14 审核修订：第 9.4–9.5 节补正整图计算所有权，第 13.2–13.5 节补齐等待调度时间并统一事件口径，第 14 节补充对应验证场景。修订仅涉及文档，工程迁移与接口实现仍待后续开展。

| 事项 | 本版约定 |
|---|---|
| 功能演示 | 先验收真实推理、原图与结果同帧、三种全屏模式及正确框与头像、连续运行和错误处理；不以达到 24/30 fps 为前提 |
| 帧率优化 | 以**实际有效输出帧率 ≥24 fps**为优化方向，达到后继续提高，不把 24 fps 当上限，也不为保留 30 fps 名义而限速 |
| 指标名称 | “有效输出帧率”指不同采集帧经过真实检测、后处理并实际显示的独立画面更新率；不是 HDMI 扫描率 |
| 模式计数 | 同一个 frame_id 切换效果仍只算一张输出帧；重复扫描、旧结果重显、仅 UI/模式变化均不增加有效输出计数 |
| 采集与显示节拍 | 按缓冲和处理能力动态接纳完整帧，结果就绪后在下一个可安全提交的输出帧边界显示；不固定每两输入帧取一帧 |
| 延迟与质量 | 延迟、更新间隔抖动、精度与稳定性单独测量；不通过降低检测质量、错帧贴图或持续排队换取较高 fps |

30 fps 可以保留为性能对照点，但不是当前交付的硬门槛。未达到 ≥24 fps 时，应如实记录“功能可用、帧率待优化”；不得把目标值写成实测值。

## 2. 总体规格与阶段边界

### 2.1 总体配置

| 子系统 | 当前规格 |
|---|---|
| FPGA/板卡 | PG2L100H-6IFBG676；沿用盘古 100pro+ / MES2L676-100HP 方向，实物版本待核对 |
| CPU | 六级单发射 RV32IMC_Zicsr，M-mode；当前范围补充并验证 Zifencei |
| CPU 存储 | 8 KiB Boot ROM、32 KiB SRAM；I/D Cache 各 16 KiB、两路组相联、32 B/Line |
| D-Cache 策略 | 写直达、写不分配；阻塞式，等待下级写响应 |
| 基础预测 | BHT 256×2 bit、BTB 128 项；支持关闭用于回归和性能对比 |
| 主逻辑时钟 | CPU、NPU、控制首版共用同一实际时钟；50 MHz 调试，100 MHz 目标 |
| NPU | 可复用 INT8 卷积运算单元，INT32 累加；默认最多 128 个乘加通路，保留 64 通路调试配置 |
| NPU 数据流 | 普通/逐点卷积与深度卷积分别映射；不把密集矩阵乘布局强套到深度卷积 |
| 模型调度 | CPU 逐算子配置；NPU 内部完成分块；同时最多一帧占用计算引擎 |
| 图像格式 | 采集/显示 RGB888；网络分支按所选 YuNet 权重转换通道顺序与数值 |
| HDMI | 一入一出，均为 800×600 @ 60 Hz，标准像素时钟 40 MHz |
| 画面内容 | 800×600 原图全屏；原图/检测框/头像按键切换，图像及结果绑定同一 frame_id |
| 原图/预览存储 | 三个帧槽，每槽 2 MiB；共享 400×300 缩小图随对应原图存储 |
| 数据与控制总线 | AXI4 数据 DMA、32 bit AXI4-Lite MMIO |
| 运行软件 | 裸机；板上执行检测后处理、帧管理和显示参数生成 |
| 当前 AI 数量 | 一个检测模型；表情仅有未启用的扩展字段 |
| 有效输出帧率 | 优化目标 ≥24 fps，越高越好；功能验收不强制达到 24/30 fps |

### 2.2 阶段验收不等于三条路线串行

| 阶段 | 验收重点 | 可暂不阻塞的事项 |
|---|---|---|
| 阶段 0：平台验证 | 六级 CPU 回归与板测；代表性 NPU 算子；固定 HDMI、DDR、全屏视频及模式切换测试 | 完整网络实时运行、最终性能 |
| 阶段 1：完整演示 | 六级 CPU 驱动真实 YuNet 推理；全画面输入；同帧全屏原图/检测框/头像切换；连续运行至少 10 分钟 | 达到 24/30 fps、最低延迟、Cache/BP 全部启用；必须报告实际有效输出帧率 |
| 阶段 2：性能优化 | 补齐两路 Cache、基础预测与规定中断；争取有效输出 ≥24 fps 并继续提高，测延迟、抖动与并发稳定性；至少 30 分钟正常运行测试 | 30 fps 不作强制门槛；表情识别、第二模型与未来 CPU 扩展不纳入 |

关键异常、AXI 完成语义、帧一致性和内存所有权从第一阶段就必须正确，不能作为以后再补的性能功能。

Cache、分支预测、NPU 优化可在首次演示前独立开发；只有通过回归的配置才合入稳定演示版本。功能正确性、CPU 特性完成情况与性能优化目标分别记录：未达到 ≥24 fps 不阻塞阶段 1 功能验收，但需保留“帧率待优化”结论；达到该目标后继续提高，不以达到 30 fps 作为完成当前功能的必要条件。

沿用已有板卡资料中的一入一出方向，不增加第二发送通道。若物理板版本不同，以原理图为准，不凭连接器外形推测接口方向。

### 3.2 固定视频时序

本版采用标准 DMT 800×600 标称 60 Hz 时序；Linux DRM 标准模式表给出的时序可用于交叉核对。[S1]

| 参数 | 水平，单位：像素时钟 | 垂直，单位：行 |
|---|---:|---:|
| 有效区 | 800 | 600 |
| 前肩 | 40 | 1 |
| 同步脉冲 | 128 | 4 |
| 后肩 | 88 | 23 |
| 总计 | 1056 | 628 |
| 同步极性 | 正 | 正 |

像素时钟为 40 MHz，单周期 25 ns。由上表计算：

```text
行周期       = 1056 / 40 MHz = 26.4 μs
扫描帧周期   = 1056 × 628 / 40 MHz = 16.5792 ms
实际扫描帧率 = 40 MHz / (1056 × 628) ≈ 60.3165 Hz
```

文中“60 Hz”是该固定视频模式的工程简称，计数和时间戳必须报告实测值，不把标准时序强行改成恰好 60.000 Hz。有效输出帧率由完整帧处理与安全显示提交能力决定，不由扫描频率直接代替，也不固定为扫描频率的一半。

输入计数、输出计数均从各自有效画面左上角 (0,0) 建立坐标，不将消隐像素计入图像。输出 HS/VS/DE 与像素流水线延迟一致。显示器会如何缩放到面板分辨率不属于 FPGA 的图像分辨率保证。

### 3.3 时钟、跨域与复位

| 时钟域 | 约定 |
|---|---|
| 主逻辑域 | CPU、NPU 和控制使用同一实际 50/100 MHz 时钟 |
| DDR 用户域 | 按厂商 IP 配置；不同于主逻辑时在统一桥接边界转换 |
| 输入像素域 | HDMI 接收侧提供，固定模式目标 40 MHz |
| 输出像素域 | 输出 PLL/板级时钟生成，固定模式 40 MHz |

输入与输出即使同为 40 MHz，也不能默认同相或没有频率偏差。使用异步 FIFO/已验证桥接传数据、握手传状态；复位在各本地域同步释放。

NPU 忙时跳过未选帧或等待下一完整输入帧，不能暂停 HDMI 时钟或破坏输出扫描。DDR 初始化失败时 CPU 应能从 ROM/SRAM 运行并报告错误。

复位、失锁和超时恢复要处理未完成 AXI 事务、旧 FIFO、旧帧元数据；当前允许受控整机重初始化，不要求无缝局部恢复。

## 4. 系统架构与三条路线职责

### 4.1 数据路径

```text
HDMI 输入：800×600 @ 60 Hz
    ↓
输入解析、帧编号、按帧采集使能、RGB888
    ├─ 完整原图写 DMA ───────────→ 帧槽 raw：800×600 RGB888
    ├─ 2:1 缩小并写 DMA ─────────→ 同槽 preview：400×300，诊断兼容
    └─ 双线性缩小＋BGR/补边/NCHW → input：320×320 UINT8
                                               ↓
                                        YuNet NPU 推理
                                               ↓
                              CPU 解码、筛选、NMS、主人脸/头像参数
                                               ↓
MODE 按键 → 单一控制所有者 → 同帧显示记录＋请求模式
                                               ↓
                        raw 行 DMA → 双 bank 行缓存 → 全屏背景
                                               ↓
                         RAW 直通 / BOX 画框 / AVATAR Alpha 混合
                                               ↓
                          安全帧边界原子提交，固定 40 MHz 扫描
                                               ↓
                            单路 HDMI：800×600，4:3 原分辨率
```

叠加在扫描流水中完成，不另外保存“已画框整帧”和“已贴图整帧”。同一处理结果可切换模式；显示持续运行，切换不重启 HDMI、DDR、采集或 NPU。

### 4.2 职责边界

| 路线 | 硬件与软件责任 | 不承担的工作 |
|---|---|---|
| CPU | 六级核、Cache/BP/异常、SoC 互连、外设驱动、模型调度、定点检测后处理、帧管理、头像参数、性能分析 | 软件卷积、大张量上采样、逐像素缩放/混合 |
| NPU | 固定 YuNet 图审计、量化/整数参考、PE/计算通路、深度卷积、辅助算子、局部缓冲与 DMA、模型包 | 任意模型编译、身份/表情网络、图级自主调度 |
| Video | HDMI/DDR 板级封装、完整帧采集、两种固定缩放、输入量化前端、三缓冲、全屏/贴图、按键模式及显示提交确认 | 检测后处理、输入人物分割、表情判断 |

模型的参考后处理和预处理数值由 NPU 路线提供；CPU 实现等价定点后处理；Video 实现逐像素预处理和显示。共同验证不等于重复各写一份规则。

### 4.3 公共模块与接口主责

| 公共事项 | 主责 | 交付要求 |
|---|---|---|
| DDR 控制器与物理封装 | Video | 一个可复用 ddr_wrapper、用户接口、约束、自检和带宽报告 |
| AXI 互连、地址和访问属性 | CPU | NPU/Video 共同使用的子集、仲裁和错误完成语义 |
| 顶层、时钟复位与约束汇总 | CPU | Video 提供像素/DDR 域约束，NPU 提供计算域条件 |
| NPU 寄存器、算子表、输出布局 | NPU | CPU 参与冻结，生成共同头文件和版本号 |
| Video 寄存器、全屏模式与提交/释放 ACK | Video | CPU 参与所有权/提交协议，像素与参数按帧绑定 |
| 输入尺度、BGR/RGB、舍入和补边 | NPU＋Video | 同一参考实现与测试向量 |
| 框、主人脸和头像坐标 | NPU＋CPU＋Video | 原图/全屏坐标一致，网络补边坐标与素材坐标分别转换 |

公共配置包含 `soc_map`、`npu_regs`、`video_regs`、`video_cfg`、`model_manifest`、`avatar_manifest`。每个字段只有一份权威定义，可生成 `.vh`、`.h`、链接片段和数据文件。

## 5. CPU 设计规格

### 5.1 当前架构与验证目标

直接以六级单发射 CPU 开发和验证，不要求先在 PG2L100H 单独完成五级交付。五级代码仅保留为历史提交、已有测试和调试参考；不得虚构同平台五/六级性能对照。

| 项目 | 规格 |
|---|---|
| 指令集 | RV32IMC_Zicsr；Zifencei 实现验证后才声明支持 |
| 执行 | 单发射、顺序执行与提交 |
| 寄存器 | 32×32 bit，逻辑上 2 读 1 写，x0 恒为零 |
| 地址与端序 | 32 bit 物理地址、Little-endian |
| 特权 | M-mode |
| 非对齐数据访问 | 按既定异常处理，不新增跨界拆分访问硬件 |
| 乘除法 | 优先复用已有乘法与迭代除法实现，检查目标器件映射 |
| 软件 | 裸机 C/汇编，不引入 FPU 来执行检测后处理 |

ISA、CSR、异常/中断和指令缓存同步应分别验证。`FENCE.I` 不是 D-Cache clean 的替代接口；程序装载完成后先确认存储写入，再同步 I-Cache 和取指前端。[B1]

```text
基础编译：-march=rv32imc_zicsr          -mabi=ilp32
扩展验证后：-march=rv32imc_zicsr_zifencei -mabi=ilp32
```

### 5.2 六级划分

```text
IF1 → IF2 → ID → EX → MEM → WB
```

| 阶段 | 功能 |
|---|---|
| IF1 | PC 选择、顺序/预测地址、发起取指 |
| IF2 | 指令返回、拼接与 C 展开，保留原始 PC、长度、异常信息 |
| ID | 译码、读寄存器、单条发射、相关性判断 |
| EX | ALU、地址计算、实际分支判断、乘除法控制 |
| MEM | 数据访问、Cache/总线等待和错误返回 |
| WB | 单条写回、退休记录与精确异常/中断边界 |

阶段边界依据实际 RAM/Cache 延迟和时序调整，但当前目标保持六级。支持 valid、停顿、冲刷和变长访存等待，不假设每条指令固定六周期结束。

取指默认 32 bit；正确处理 C 指令跨取指字、跨 Cache Line 与异常。当前不新增 64 bit 双指令前端、双写回口、第二发射槽或双发射旁路。

### 5.3 Cache、预测与异常

沿用此前已约定的两路 Cache 与写直达策略，不因更换应用而降低 CPU 完成目标。[B1][B2]

| 项目 | 当前约定 |
|---|---|
| I/D Cache | 各 16 KiB、2-way、32 B/Line、Blocking |
| D-Cache 写命中 | 下级写成功后更新命中行，支持字节使能 |
| 写缺失 | 写下级、不分配，不产生脏行 |
| 写错误 | 返回访问异常，相关命中行失效，禁止错误值命中 |
| Store 完成 | 等待下级响应，不提前确认 |
| MMIO/共享 DMA 数据 | 不可缓存，禁止以可缓存别名访问 |
| FENCE | 对既定访问类型等待和排序 |
| 预测器 | BHT 256×2 bit、BTB 128 项，EX 恢复；RAS 不纳入首版 |
| 关闭配置 | 阶段 1 可关闭 Cache/BP；阶段 2 纳入功能和性能验收 |

支持所需 `mstatus/mie/mip/mtvec/mepc/mcause/mtval/mscratch`、机器信息寄存器和 `MRET`；验证非法指令、ECALL/EBREAK、访问错误、非对齐数据访问、陷入与中断返回。[B1]

运行初期可用轮询 NPU；不能因为未启用设备中断就阻塞演示，也不能因此删除基本异常或错误路径。完整中断与 CPU 特性属于阶段 2 当前完成目标。

### 5.4 CPU 评估

从六级核首次可运行即测 CoreMark、主频、LUT/FF/DRM/APM 和提交轨迹；随后分别比较 Cache/BP 配置、访存与视频/NPU 并发影响。

保留周期、退休指令、Cache Miss、分支误预测、访存和相关性停顿计数。功能未启用时不生成伪指标。

CoreMark 固定编译选项与存储位置，运行不少于 10 秒并通过校验。[S8] 报告 CoreMark、CoreMark/MHz、CoreMark/LUT 及实际闭合主频，不将不同平台的数据作为未经说明的架构对照。

## 6. YuNet 模型与部署边界

### 6.1 模型基线

| 内容 | 当前约定 |
|---|---|
| 主候选 | OpenCV Zoo 的 YuNet |
| 浮点权重起点 | `face_detection_yunet_2023mar.onnx`，记录来源、获取版本与 SHA-256 |
| 检测任务 | 人脸框、置信度、五个关键点；不预测身份或表情 |
| 当前输入契约 | UINT8 BGR NCHW `[1,3,320,320]`，按外部 NPU 提交 4fc0fc8 适配 |
| 有效图像 | 320×240，上下各补 40 行零 |
| 初始策略 | 保留预训练结构；先部署适配，精度不足后才考虑 QAT |
| 正式冻结条件 | 浮点效果、固定形状导出、算子清单、整数参考及周期预算通过共同审查 |

OpenCV Zoo 指出 `2023mar` 是固定输入图，并提供其他形状导出路径；本版不以“文件名叫 YuNet”代替版本冻结，也不假定修改一个输入尺寸字段就完成所有形状适配。[S2]

外部模型与输入数值交接审计见 [NPU 交接记录](verification/video/npu_handoff_audit.md)。已冻结输入适配不等于 NPU RTL、正式输出 ABI 或整网硬件推理已验收；人脸大小、距离、位置与遮挡的效果仍须独立评估。

### 6.2 必须进行的图审计

离线工具输出逐层表：算子类型、输入/输出形状、有效/存储通道、卷积核、stride、padding、groups、权重/量化格式、生命周期、搬运字节数和预计周期。

作者公开实现包含逐点/深度卷积、ReLU、池化以及上采样相加的特征融合。[S4] 这些用于准备硬件能力；**固定权重导出图才是最终算子清单**，不能将当前训练仓库源码与历史 ONNX 视为未经核对的完全相同版本。

图审计须标出 BN 融合、Sigmoid 的执行位置、Reshape/Transpose 如何映射，以及所有浮点或软件回退。未支持的大张量操作不能静默放到 CPU。

### 6.3 输入预处理与数值

沿用已由用户选定的外部 NPU 输入契约，固定参考提交 `4fc0fc882a6e92ec662a4f9b27b105182da444b8`、预处理版本 1：

```text
完整 800×600 RGB888
→ 按冻结 OpenCV 4.11 INTER_LINEAR 数值缩至 320×240
→ 通道转为 BGR
→ 上下各补 40 行原始值 0
→ UINT8 NCHW 三平面，scale=1，zero-point=0
```

物理内存也采用 NCHW，B/G/R 各一平面；行步长 320 B，平面步长 102400 B：

```text
3 × 320 × 320 × 1 B = 307200 B = 300 KiB
每输入槽预留 320 KiB，三槽布局见第 10.3 节。
```

上下补行均为 0，不添加 C8 通道或额外 `/255`。软件参考、RTL 舍入与张量哈希见
[320 数值参考](verification/video/yunet320_reference.md)、[双线性 RTL](verification/video/detect_bilinear.md)和
[NCHW DMA](verification/video/nchw_dma.md)。早期 160×128/C8 组件仅保留为独立历史验证，不能用于本版正式输入。后续内部激活/权重量化由模型包单独冻结。

### 6.4 量化与整数参考

| 数据 | 基线约定 | 待验证内容 |
|---|---|---|
| 权重 | 对称 INT8，逐输出通道 scale，zero-point=0 | 包括深度卷积逐通道尺度 |
| 激活 | 优先有符号 INT8、逐张量 scale、zero-point=0 | 输入非负值域利用率、敏感层截断及整体精度 |
| Bias/累加 | INT32 | 分块和最大可达值，禁止静默溢出 |
| 检测头 | 优先 INT16 原始回归值/概率前 logits | 每个输出的 scale 和 Sigmoid 归属 |
| 算术规则 | 明确舍入、移位、饱和、查表范围 | C/Python/RTL 必须一致 |
| Add | 两输入转换到约定尺度后相加和重定标 | 不直接相加不同尺度的整数 |

对称量化是降低硬件复杂度的起点，不保证尚未评估的数据上精度足够。输入、激活或输出格式需要调整时，先更新模型包及实现约定，不以隐藏浮点回退修补结果。

先做 PTQ 校准、逐层误差定位；仍不满足效果时再决定 QAT。QAT 必须模拟实际舍入、饱和和算子边界，不能替代正确的图转换。[S5]

OpenCV Zoo 中 `int8bq` 及其权重块量化工具不等于本版完整 W8A8 整数执行，须核查反量化和实际算子类型。[S2][S6]

### 6.5 输出与后处理边界

OpenCV 参考接口按 stride 8、16、32 读取 `cls/obj/bbox/kps` 四组输出；框与五点解码由 CPU 后处理完成。[S3]

以下 160×128 的 420 位置推导保留为早期评估记录，不是当前 320×320 输出 ABI。当前若沿用 stride 8/16/32，位置数为 40×40＋20×20＋10×10＝2100；最终输出 dtype、布局、Sigmoid 与缓冲长度须按模型交付重新冻结。早期推导为：

```text
stride 8：20×16 = 320
stride 16：10×8 = 80
stride 32：5×4 = 20
总计：420 个预测位置
```

每位置的逻辑输出为 `1 cls + 1 obj + 4 bbox + 10 kps = 16` 个值，不是推文自训模型的 20 个字段，也没有原生逐关键点置信度。[S3][B3]

若全部采用 16 bit，紧凑逻辑数据为 420×16×2 = 13,440 B。若四组独立按 8 通道对齐，则约为 420×(8+8+8+16)×2 = 33,600 B。以上是形状推导；最终顺序、步长、对齐和是否已有 Sigmoid，以导出清单为准。

本版优先在 CPU 使用定点 LUT 执行筛分数所需的 Sigmoid，NPU 输出对应 logits；这是部署边界调整，不是删掉数学运算。只有提取前 Sigmoid 输出并做等价检查后才启用。若导出图保留 NPU Sigmoid，清单必须明确标记，CPU 不重复执行。

### 6.6 模型数据与验收资料

使用公开预训练模型建立基线，准备与实际拍摄距离和光照相近的校准图像，以及独立的带框验证图像/视频。素材来源、授权、数据划分和校验值入库，不把校准数据反复当作最终测试集。

校准不要求表情标签；表情数据不进入本版验收。对参与演示的人像取得适当同意，不构建身份数据集。

必须交付：浮点参考、硬件整数参考、图审计表、量化参数、权重布局、张量内存规划、C 算子表、逐层测试向量及对比报告。精度按同尺寸、同预处理、同候选规则比较，报告框召回/误检和量化差异；具体数据量及绝对精度门槛在阶段 0 冻结，不虚构已达数值。

## 7. NPU 规格

### 7.1 计算通路与控制

保留可复用的 INT8 卷积加速思路，默认计算资源上限为 128 个 INT8 乘加通路，支持 64 通路调试。资源预算按一个 APM 对应一个主要乘法通路起算，不以 APM 打包多个乘法为前提。

不再要求所有算子都强行映射到两个固定的 8×8 密集脉动阵列。已有 PE/阵列代码可用于普通卷积；深度卷积必须有合适的供数、独立通道累加和执行模式。两种模式共享乘法资源或采用小型辅助通路，额外资源须单列预算。

| 模式 | 必须保证 |
|---|---|
| 普通/1×1 卷积 | 输入通道归约正确；可按输出通道和空间位置并行；部分和保留 |
| 深度卷积 | 每个通道独立；按通道/空间并行，不混加不同通道；不把稀疏连接展开成大量零权重普通卷积 |
| 辅助算子 | 使用局部缓冲和 DMA，不交给 CPU 逐元素处理整个特征图 |
| 调度 | CPU 按算子启动；NPU 内部遍历 tile，单算子执行 |
| 并发 | 一个推理任务；允许与下一帧采集和当前显示重叠，不代表两个模型并行 |

阵列几何形状与深度卷积实现方式须通过代表性层比较后固定；128 是资源与峰值规模，不是每个算子每周期均完成 128 次有效乘加的保证。

### 7.2 算子能力

| 算子 | 当前实现要求 |
|---|---|
| 普通 Conv | 固定图需要的 3×3 与 1×1、stride/padding；首层有效通道 3 |
| Depthwise Conv | 固定图需要的 3×3、通道独立、stride/padding |
| Bias/BN | 离线融合 BN，硬件加整数 Bias |
| Requantization | 乘系数、移位、舍入与饱和 |
| ReLU/线性 | 图中规定的激活或旁路，不无条件给所有输出加 ReLU |
| MaxPool | 准备 2×2 下采样模式，最终核和步长以图审计为准；若有边界，按最小值而非默认零补齐 |
| Add | 输入尺度对齐、相加、输出重定标 |
| 最近邻上采样 | 2 倍空间映射，语义以固定图为准 |
| 张量重排 | 离线布局、地址/步长或明确 DMA 复制，不忽略实际数据顺序 |
| 检测头概率变换 | 按第 6.5 节分配，不重复计算 |

不再为了旧应用要求 6×6 首层、SiLU、SPPF 或旧检测头专用路径。新发现的算子必须登记归属与代价，不能以“其他层”隐藏 CPU 回退。

### 7.3 局部缓冲与搬运

输入 tile、权重 tile、INT32 部分和、输出工作区可以沿用各 32 KiB 的起始容量规划；深度卷积窗口和辅助操作共享或追加银行资源，需重新核算端口与占用。

跨输入通道块累加时，INT32 部分和保留至当前输出完整，不允许每块先截断 INT8。卷积窗口在片上生成，不向 DDR 写完整 im2col 矩阵。

最初允许搬入、计算、搬出串行，后续按最慢层加入局部双缓冲。没有实现并验证重叠时，周期预算必须相加；不能预先把 DMA 等待抵消。

### 7.4 逐层周期评估

普通分组卷积的有效 MAC 数按 `Ho×Wo×Co×(Ci/G)×Kh×Kw` 统计，深度卷积使用其真实分组，不套用普通密集卷积。[S4]

每层记录：有效 MAC、发起周期、填充/尾块、权重和激活搬运、辅助算子周期、DMA 等待和总周期。密集与深度卷积分别测利用率。

128 通路、100 MHz 的算术峰值为 12.8 GMAC/s，仅用于下限估算。没有完成本版 YuNet 图统计前，不写入预期整网 MAC 数或承诺推理毫秒数；不引用手机、STM32 或 GPU 的帧率作为本平台保证。

## 8. 视频采集、缩放与全屏显示

### 8.1 完整采集与数据分支

每个被选中的完整输入帧同时生成原图、共享显示缩小图、检测输入。三者使用同一 `frame_id`，生成完成且各 DMA 写响应完成后，才置 `CAPTURE_DONE`。

输入帧必须在帧边界接受或放弃，不从中间开始拼接。未选帧仍解析同步；禁止因 NPU 背压而暂停 HDMI 输入。

### 8.2 固定检测缩放

正式输入按第 6.3 节由 800×600 缩至 320×240，再上下各补 40 行，形成 320×320 BGR NCHW。
`detect_bilinear` 的 5:2 相位与分步取整以冻结的软件参考为依据，不另用 5×5 块平均替代。
原始图像的全部范围参与检测缩放；显示模式选择不修改这条预处理链。

### 8.3 诊断兼容的显示缩小图

采集时生成一份 400×300 RGB888 图，对输出像素 (u,v)：

```text
preview(u,v) = floor((P(2u,2v) + P(2u+1,2v)
                    + P(2u,2v+1) + P(2u+1,2v+1) + 2) / 4)
```

原图是正式全屏显示的背景来源，也可用于裁脸扩展与问题定位。400×300 preview 保留供既有双窗诊断、CRC 和三分支完成契约使用；正式显示不从它放大取图。本次不删除其写 DMA 或改变 CAPTURE_DONE 依赖。

### 8.4 全屏布局与按键模式

有效区为 `0≤x<800、0≤y<600`，raw `(x,y)` 直接映射至输出 `(x,y)`，完整保留 4:3 和原分辨率。状态优先经串口/计数器报告；可选小型 OSD 叠加在图像上，不预留上下 150 行，不压缩背景。

| 模式 | 编码 | 输出内容 |
|---|---:|---|
| RAW | 0 | 同帧完整原图，关闭检测框/头像叠加 |
| BOX | 1 | 原图＋最多 16 个检测框；五点可独立关闭 |
| AVATAR | 2 | 原图＋一张选定主人脸头像；默认关闭检测框 |

启动默认 RAW；MODE 短按循环 RAW→BOX→AVATAR→RAW。异步按键先同步，再要求稳定按下和稳定释放各 20 ms；长按不连发。KEY0 继续承担协调复位/重采，不复用为模式切换。MODE 的板级管脚/电平须按原理图单独发布，不能仅凭 KEY1 名称接线。

按键/软件只更新请求模式，由唯一控制所有者合成完整影子记录。模式、原图地址/步长、frame_id、检测与素材参数在安全输出帧边界一起提交。准备不足则继续显示旧的完整记录；无半帧切换、重新采帧或重新推理。模式请求等待期间，多个按键按循环累计至最后请求值；只有最后请求保证提交，合并情况记入计数。BOX/AVATAR 需同帧有效检测结果和对应能力；尚未实现/结果未就绪时显式报告 unavailable/pending，不能显示旧帧参数。

显示从 raw 按行预取到双 bank 缓存，每 bank 800×3＝2400 B；未完成该行全部像素消费及流水退休前禁止覆写。新帧首行及必要叠加数据准备好后才可提交。两 bank 共 4800 B 是有效数据量，实际 DRM 数量按宽度/端口和综合报告计算。

### 8.5 坐标映射

CPU 保存原始 800×600 图像坐标；全屏输出坐标与原图坐标相同。对已按模型规则解码的连续框/关键点坐标，当前 320×320 输入的有效区为 `0≤x_net<320、40≤y_net<280`：

```text
x_raw = x_net × 800/320 = 2.5 × x_net
y_raw = (y_net - 40) × 600/240 = 2.5 × (y_net - 40)
x_display = x_raw
y_display = y_raw
```

该式是检测几何坐标还原；像素缩放仍使用第 6.3 节冻结的采样与舍入，不把双线性像素中心公式混入框解码。额外 ROI、左右窗口偏移和旧 1:5 比例均不适用。

运算先保留足够定点精度，最后栅格化。框为 `[x0,x1)×[y0,y1)`；左上 floor、右下 ceil，裁到 `[0,800)×[0,600)`，零面积框删除。中心落在上下补边的候选删除，跨有效区边界的框裁剪；参考与 CPU 使用同一规则。关键点取最近像素并单独检查有效性。

### 8.6 检测框和头像像素处理

BOX 模式默认最多显示 16 个 NMS 后框，主人脸可使用独立边框样式。五点作为可关闭的调试显示；无逐点原生置信度时不得伪造置信度，几何有效标志与网络输出字段分开。

AVATAR 模式只叠加一张主人脸头像。默认最近邻缩放和平移，不做任意角度旋转、分割或三维变形。头像占用矩形由 CPU 根据原图框、素材锚点和覆盖系数生成，按全屏原图边界裁剪；覆盖系数在素材验证时冻结，不承诺所有侧脸均完全遮住。

素材离线转换为 RGBA8888、非预乘 Alpha，当前按 256×256 的素材规格准备。每张 262,144 B；素材索引和锚点写入清单，运行时不解析 PNG。

每个通道的混合规则为：

```text
out = floor((alpha × avatar + (255-alpha) × background + 127) / 255)
```

alpha=0 必须精确输出背景，alpha=255 必须精确输出素材。最近邻源地址从未裁剪的目标矩形计算；只裁输出范围，不能让靠边头像被错误压缩。

素材行由 DMA 预取和缓存，逐像素读取/缩放/混合由 Video 完成；CPU 只提交地址、avatar_id、位置、尺寸及锚点。插入流水级后同步延迟像素、DE、HS/VS 和模式/叠加标志，40 MHz 扫描不得被暂停。

### 8.7 有效结果与失效行为

有效无脸帧：三种模式均显示完整原图，BOX/AVATAR 的叠加为空，并可报告“无脸”。关键点无效但框有效：允许仅用框定位头像。多脸：BOX 可显示多个框，AVATAR 只替换选定主人脸，不声称身份跟踪。

推理超时或输出无效：不得将旧头像参数提交给新帧。可保持上一张完整有效画面并标明过期/错误；没有任何有效帧时输出本地背景。

关闭跨帧框坐标平滑作为初始默认，先证明同帧贴合。后续加入平滑时必须评估位置滞后，不能借此掩盖帧不一致。手部遮挡和头发边界不做真实遮挡恢复，演示中明确为二维贴图效果。

## 9. 帧缓冲、运行重叠与完成语义

### 9.1 三帧槽而非两份输出缓存

每个帧槽绑定：原图、共享显示缩小图、检测输入、检测输出区域、检测/头像参数及时间戳。三个槽可轮流处于采集、处理、显示状态。

三个效果模式复用同一原图与结果，正式扫描读取 raw，preview 保留诊断；NPU 同时只处理一帧。允许“采集下一帧、处理当前帧、显示上一完成帧”重叠，用于提高有效输出帧率、降低等待并争取 ≥24 fps；这不是多 NPU 或多帧计算并行，也不将吞吐限制为 30 fps。

阶段 1 可以先按需采帧、串行证明功能，随后在相同所有权协议上启用重叠。不能只把单个输入缓冲改名为乒乓，就同时允许采集写入和 NPU 读取它。

### 9.2 状态和所有权

| 状态 | 含义 | 允许的访问 |
|---|---|---|
| FREE | 没有任何活跃消费者 | 可被采集器预留 |
| CAPTURING | 完整帧采集及三分支 DMA 正在进行 | 只由采集/预处理写入 |
| READY | 三份输入数据完整且写入完成 | 等待调度，原始数据只读 |
| PROCESSING | 当前帧正在 NPU/CPU 处理 | 检测输入只读；输出和结果由本帧任务写入 |
| READY_DISPLAY | 检测后处理与头像参数均完成 | 等待显示原子提交，禁止覆盖 |
| DISPLAYING | 输出扫描使用该槽的 raw 原图和同帧参数 | 显示读取、禁止采集覆写 |
| RETIRING | 已切走但旧 DMA/FIFO 引用未清完 | 等待显示释放确认 |
| INVALID | 采集、推理或 DMA 错误 | 排空相关访问并完成受控恢复后才可释放 |

状态由统一驱动/硬件握手管理，不由 CPU、NPU、Video 各维护一份不一致的布尔标志。复位后丢弃所有旧任务，首帧就绪前显示本地背景。

### 9.3 采集和显示协议

| 事件 | 必须满足的条件 |
|---|---|
| CAPTURE_ACCEPTED | 在完整输入帧边界锁存帧槽地址和 frame_id |
| CAPTURE_DONE | 原图、显示缩小图、网络输入写完且写响应成功；像素/尺寸检查通过 |
| INPUT_READY | 与本帧 CAPTURE_DONE 对应同一个逻辑就绪事件，三分支均完成后发布；不是单独的 INPUT_WRITE_DONE |
| NPU_DONE | 所有当前算子输出写完成，才允许 CPU 或下一算子读取 |
| RESULT_READY | 框、主人脸、头像参数和图像地址属于同一帧，CPU 写入已完成 |
| DISPLAY_COMMIT | 在安全输出帧边界原子切换 raw 地址、模式、框/头像/状态参数与 frame_id |
| DISPLAY_RELEASE_ACK | 旧显示 DMA、预取和 FIFO 不再引用旧槽，才允许复用 |

`DISPLAY_COMMIT` 不是旧槽立即可写的充分条件。旧 raw DMA、预取、行缓存及像素流水全部不再引用旧槽后，才能 DISPLAY_RELEASE_ACK。同一 frame_id/槽仅切换模式时继续持有原槽，不产生该槽释放；新帧与模式同边界提交时按一个完整记录处理。

在显示提交与旧槽释放之间，CPU 可能短暂无 FREE 槽。按截止时间分析与测试确定三个槽是否足够，不能用“有三缓冲”替代占用周期证明。

### 9.4 按能力接纳输入、有效输出与积压控制

不再固定“每两个输入扫描帧选一个完整帧”，也不规定每张结果恰好重复扫描两次。默认按缓冲与处理能力动态接纳：有安全可写帧槽且不会形成持续积压时，在下一输入帧边界接收完整帧；无活跃整图任务且 NPU 空闲后及时处理就绪帧。

结果进入 READY_DISPLAY 后，在下一个满足第 9.3 节提交条件的输出帧边界显示。没有新结果时继续扫描上一张完整有效画面，不暂停 HDMI，也不把重复扫描记为新输出。测试需要限速时可由软件设置采样策略并写入记录，正常优化配置不强制限速为 24 或 30 fps。

输入/输出实际时钟有偏差时，允许有记录的节拍适配，不能无限积压。采集、检测完成和有效输出可能具有不同帧率，应分别统计；已算完但未真正显示的帧不能计入有效输出帧率。

没有空闲槽时跳过整帧，不覆盖 PROCESSING 或 DISPLAYING 数据。READY 或 READY_DISPLAY 队列中的过期帧，仅在尚未被消费者接纳/引用、并记录丢弃原因后可释放；提交已锁存的显示记录不可用另一帧暗中替换。任何低延迟丢弃策略均须维持显示 frame_id 按时间前进。

计数区分：主动抽帧、无空槽丢帧、处理超时、未显示即丢弃、重复扫描、错过已配置的诊断截止时间，以及时钟节拍适配。未配置固定更新时隙时，不把未产生新结果的每次扫描都记为“30 fps 超期”。

优化原则是提高**真正完成推理并显示的帧数**，同时控制输出间隔抖动、队列驻留时间和错误。不能靠重复旧图、只更新 UI、同帧的不同效果各计一次或长期缓存积压来提高数字。

### 9.5 建议的事件驱动调度

```text
启动并校验模型/素材/接口版本，初始化三帧槽；graph_active=0，frame_owner 无效

循环处理事件：
    若有 FREE 槽且可接纳新任务：提交下一完整帧采集请求（不固定每两帧一次）
    若 CAPTURE_DONE：确认三分支写完，记录 INPUT_READY，槽进入 READY
    若 graph_active=0、NPU IDLE 且有 READY 槽：
        锁定 frame_owner 和共享模型工作区，置 graph_active=1
        槽进入 PROCESSING，记录 DET_START，开始该帧算子表
    若当前算子完成且还有后续算子：只继续 frame_owner 的下一算子
    若最后算子输出写完成：记录 DET_DONE，执行该帧有限候选解码、NMS、主人脸和头像参数计算
    若后处理完成且结果写入完成：记录 RESULT_READY，将该槽标记 READY_DISPLAY
        确认共享模型工作区无本帧消费者后，清除 graph_active 和 frame_owner
    有 READY_DISPLAY 结果时：在下一可安全提交的输出帧边界原子提交同帧 raw/模式/叠加参数
    收到 DISPLAY_RELEASE_ACK：释放旧槽
    出错或超时：作废相应任务，停止接纳新计算任务，进入恢复
        排空相关访问并确认共享工作区可安全复用后，才清除计算所有权
```

`graph_active/frame_owner` 是软件整图调度状态，不是新增 NPU 图级硬件队列。硬件 IDLE/BUSY 只描述单算子；算子之间的空闲不能触发另一帧插入当前算子表。帧相关事件必须核对 frame_id，NPU 算子完成/错误事件还须核对 OP_TAG，旧事件不得推进其他任务。

上述首版调度将计算所有权保留到 RESULT_READY，不等待该帧显示完成；下一帧采集和上一帧显示仍可重叠。后续若让 CPU 后处理与下一帧 NPU 执行重叠，须单独验证分槽输出、CPU 工作区和共享中间张量的生命周期，再调整所有权释放点。

CPU 可以采用中断事件加主循环，也可以先轮询；不得因等待某个算子或执行后处理而忽略已经到来的显示释放和错误事件。采集/显示 DMA 持续工作，CPU 不逐像素服务。

### 10.1 总线约定

| 接口 | 当前决定 |
|---|---|
| CPU 存储接口 | 复用 32 bit 指令/数据接口，桥接到 SoC 互连，支持 Cache 行突发 |
| 控制寄存器 | 32 bit AXI4-Lite |
| 数据 DMA | 以 128 bit AXI4 为逻辑目标，适配 DDR IP 实际宽度/时钟 |
| Burst | INCR，起始上限 16 beat，拆分 4 KiB 边界和尾部字节 |
| 未完成事务 | 首版每主端读/写各最多一个；扩展必须重测顺序和缓冲 |
| 仲裁 | 显示 FIFO 危险水位优先，正常有界轮询，所有主端有可验证的最大等待约束 |
| 复位/错误 | 不静默吞掉错误响应，不带残留事务复用数据缓冲 |

优先复用已验证互连和厂商 IP，不实现与当前任务无关的完整多 ID 乱序 Crossbar。RGB888 行不一定整除每次 burst，使用明确的字节使能与行尾规则。

### 10.4 带宽预算

`f_cap` 为实际完整帧采集率，`f_scan` 为 HDMI 扫描率；模式切换不降低扫描读取量。当前三分支采集继续运行，正式全屏每次扫描从 DDR 读取一份完整 raw：

```text
B_base = (1440000 + 360000 + 307200) × f_cap
         + 1440000 × f_scan                         [B/s]
```

仅作量级示例，取 `f_cap=24`、名义 `f_scan=60`，MB 为十进制：

| 数据流 | 每帧/次扫描数据量 | 示例每秒流量 |
|---|---:|---:|
| raw 采集写入 | 1440000 B | 34.56 MB/s |
| 诊断 preview 生成写入 | 360000 B | 8.64 MB/s |
| 320×320 BGR NCHW 写入 | 307200 B | 7.3728 MB/s |
| 全屏 raw 显示读取 | 1440000 B/次扫描 | 86.4 MB/s |
| **基础合计** | — | **136.9728 MB/s** |

固定 DMT `f_scan=40000000/(1056×628)≈60.316541 Hz` 时，显示读取约 86.855819 MB/s；`f_cap=24` 基础合计约 137.428619 MB/s。若完整采集也达到该扫描率，基础合计约 213.954835 MB/s。这些均不含 NPU 输入/权重/特征图/输出、CPU、头像 DMA、协议及刷新开销，也不是实测吞吐。

旧双窗行缓存每扫描读取 360000 B；全屏 raw 读取量是其四倍。将 preview 放大到全屏若具备行/像素复用可保留低读取量，但会损失原始清晰度，因此不作为正式原分辨率方案。当前先保留 preview 写入；后续删除时要连同三分支完成契约和测试一起修订。

全屏每活动行读取 2400 B，即 150 个 128bit beat；像素有效期间背景消耗率为 40M×3＝120 MB/s。行周期 26.4 μs，行缓存预取必须在实际消费截止时间前完成；首行要在提交前准备好，不能沿用旧布局顶部 150 行的准备时间。头像按目标矩形、缓存复用和素材格式另计流量/突发；屏幕覆盖面积可达 800×600，不能沿用旧 400×300 覆盖范围预算。

128bit/100MHz 的理论 1.6 GB/s 不代表实测 DDR 吞吐。测试必须注入采集＋显示＋头像＋NPU＋CPU 争用，记录有效吞吐、最长仲裁等待、bank 归还、FIFO 水位和欠载；先验收行截止时间，再评估 ≥24 fps 优化目标。

### 10.5 一致性与顺序

CPU 私有程序、栈与候选工作区可缓存；DMA 共享数据和 MMIO 不可缓存，禁止共享数据的可缓存别名。写直达不自动使 DMA 写入后的 CPU Cache 副本失效。

输入/输出/显示提交均遵循写完成和内存屏障约定。缓存属性、总线顺序、帧所有权分别处理；`FENCE` 不自动清理任意 Cache 内容。[B1]

## 11. NPU、Video 与软件接口

### 11.1 模型控制

离线生成固定 YuNet 的 C 算子表，由 CPU 逐算子写 MMIO；NPU 内部执行分块循环。没有硬件图级取指，没有通用 ONNX 解释器，不让 CPU 为每个 PE 或窗口下命令。

算子参数包括输入/输出/权重/Bias/量化地址、形状、步长、核、stride、padding、group/mode、有效通道、输出格式以及帧/算子编号。深度卷积模式必须显式编码，不能依靠模块内部猜测。

### 11.2 NPU 寄存器起点

| 偏移 | 名称 | 语义 |
|---|---|---|
| `0x00` | ID_VERSION | 硬件及接口版本 |
| `0x04` | CAPS | 普通/深度卷积和辅助算子能力、实际并行度 |
| `0x08` | CONTROL | START，仅 IDLE 接受 |
| `0x0C` | STATUS | IDLE/BUSY/DONE/ERROR |
| `0x10` | IRQ_STATUS | 完成/错误，写 1 清除 |
| `0x14` | IRQ_ENABLE | 完成/错误中断使能 |
| `0x18` | ERROR_CODE | 错误原因 |
| `0x1C` | OP_TAG | 当前算子编号 |
| `0x20` | FRAME_ID | 帧编号 |
| `0x24` | TOTAL_CYCLES | 算子总周期 |
| `0x28` | COMPUTE_CYCLES | 有效计算周期 |
| `0x2C` | DMA_WAIT_CYCLES | 搬运等待周期 |
| `0x100` 起 | OP_PARAMS | 上述地址、维度、步长和数值参数 |

START 原子锁存参数，BUSY 时禁止修改活跃任务。DONE 晚于所有输出写响应成功；致命错误使整帧作废，不以超时后读取旧输出继续显示。计数器初始每算子 32 bit、CPU 汇总 64 bit，检查溢出。

### 11.3 Video 控制寄存器起点

独立显示ABI1使用`config/video_display.json`同源生成RTL/C。Video区域仍为
`0x20010000/64KiB`，显示子窗口为`0x20011000/4KiB`，正式fabric必须先子译码。
原未发布草案的0x30/0x200显示偏移不再作为新显示端点地址，既有采帧寄存器不改义。

| 相对Video基址偏移 | 当前契约 |
|---|---|
| `0x00–0x1C` | 采帧版本、能力、控制、状态、中断、错误 |
| `0x20–0x2C` | 采帧请求、状态、已接受/完成frame_id |
| `0x100–0x1BC` | 采帧shadow/接受/完成记录，保持ABI1 |
| `0x1000–0x1080` | 独立显示版本/能力/状态/IRQ、提交、mode/seq、active/commit/release/reject事件及计数 |
| `0x1100–0x137F` | 640B显示shadow：32字头部＋16框×8字，五点与素材参数同帧冻结 |

显示子窗口内`+0x20` SUBMIT全字1新帧/3同帧MODE；B OKAY仅表示本地接纳校验任务。
整记录和首行/资源准备、实际安全帧边界提交、末端像素与旧引用退休各自分离。
`+0x14` EVENTS位0/1/2/3为commit/release/reject/fault，`+0x18` ACK位0/1/2消费

### 11.5 固定点后处理

先读取 cls/obj，执行必要概率转换和阈值筛选，再解码保留候选。NMS 前 Top-K 的起始建议为 128，BOX 模式最多 16 框；阈值和候选截断在阶段 0 根据验证数据冻结，不照抄推文阈值。

YuNet 参考分数是 `sqrt(cls×obj)`。[S3] 对非负概率的阈值/排序，可在正确统一尺度后比较乘积及阈值平方，避免所有候选开平方；这项实现优化要与同规则参考核对。

框宽高的指数、必要 Sigmoid 用经过范围分析的定点查表。CPU 临时计算范围使用足够的位宽；分数乘积、IoU 交叉乘积和坐标裁剪检查溢出，不因 RV32 而默认所有中间量都能装入 32 bit。

NMS 后选有效面积最大的人脸为主人脸；同面积按分数，再按固定候选顺序决胜，保证可重复性。当前不依赖追踪上一帧才能运行；不承诺多人进出时替换对象保持同一身份。

## 13. 资源与性能评估

### 13.1 FPGA 资源基数

PG2L100H 预算基数为 66,600 LUT、133,200 FF、155 个 36 Kbit DRM、240 个 APM，须与 PDS 目标器件核对。[S7]

旧应用的资源占用表没有本版深度卷积、共享预览、Alpha 贴图和三槽管理的实测依据，不能直接继续宣称整机占用为旧预算值。本版按下表逐步填充：

| 部分 | 当前能确定的内容 | 需要交付的结果 |
|---|---|---|
| 六级 CPU/Cache | 继承当前 CPU 配置，不增加双发射 | LUT/FF/DRM/APM 与闭合时钟 |
| NPU 主计算 | 64/128 通路配置；128 是主要乘法规模 | 各模式周期、额外量化/DW 资源、完整时序 |
| 局部缓冲 | 起始 tile 容量与银行规划 | 实际 DRM 映射和端口供数 |
| Video | 全帧、两种缩放、共享行缓存、头像预取/混合 | 各缓冲、APM/LUT、40 MHz 时序与 DDR 压力 |
| DDR/互连/调试 | 复用厂商 IP 和受限互连 | 总体布局布线占用及剩余空间 |

APM 辅助乘法、Alpha 混合和量化不能都计入 NPU MAC 峰值。未完成模块不填入看似精确的综合数，留足调试和布线空间，再决定是否扩大并行度。

### 13.2 性能指标与含义

| 指标 | 当前目标/口径 |
|---|---|
| HDMI 扫描 | 固定模式连续输出，标称 60 Hz；这是接口要求，不是 AI 帧率 |
| **有效输出帧率（主要优化指标）** | **争取 ≥24 fps，在检测效果、同帧对应和稳定性不退化的前提下越高越好；30 fps 不强制，也不作为限速上限** |
| 实际检测帧率 | 按不同 frame_id 的 RESULT_READY（检测后处理、头像参数及结果写入完成）计数，单独报告；DET_DONE 不计完成帧，不能用检测帧率替代已经显示的帧数 |
| 独立显示更新 | 新完成且已真实处理的 frame_id 首次全屏可见计一帧；重复扫描、旧帧、模式/OSD 变化均不增加 |
| 完整处理时间 | INPUT_READY 至 RESULT_READY，含等待调度、真实图执行与后处理；测平均和分位数，不再固定套用 30 fps 的 25 ms 门槛 |
| 低延迟方向 | 保留板内可见延迟 P95≤50 ms 的独立优化参考，先测量再优化；不作为首次功能演示门槛，也不由输出 fps 直接推导 |
| 早期演示 | 先正确运行、连续显示并记录实际 fps；未达 ≥24 fps 可标记“功能可用、帧率待优化”，不称已达到该优化目标 |
| 表情刷新/响应 | 当前未实现，不提供该项性能数字 |

**主要指标定义：**

```text
F_output = N_new_displayed / T_wall
```

`N_new_displayed` 为统计窗口内首次实际显示的不同采集 frame_id 数，每帧必须完成本帧真实检测及后处理，且原图和结果一致；以 `SHOW_FRAME_FIRST` 记录首个有效输出像素，并绑定当前模式与 frame_id。有效“无脸”结果正常计入；推理失败后重复显示的旧帧不计新帧。统计区间采用统一时间基准 `[t0,t1)`，`T_wall=t1-t0`，不得只累加 NPU 忙碌时间作为分母。模型装载与预热单列，稳态窗口内的等待、重复扫描和额外掉帧不能从时间中扣除。

同一 frame_id 在 RAW/BOX/AVATAR 间切换不增加有效输出帧数；MODE_COMMIT 单独计数。RAW 诊断中未运行真实检测的原图刷新只报 raw 显示更新率，不混入完整应用的有效输出 fps。已完成检测但未显示的结果只计检测吞吐和丢弃。

按长期平均节拍换算：

```text
24 fps ↔ 1000 / 24 ≈ 41.67 ms/独立输出帧
```

41.67 ms 仅用于吞吐预算和更新间隔比较，不是 NPU 每帧必然可独占的时间，不是每次显示间隔的硬上限，更不是某帧从输入到可见输出的延迟保证。提高输出帧率仍须测量采集、计算、CPU 后处理、输出相位、提交提前量和扫描流水偏移，并为实际波动保留余量。

性能比较必须记录相同模型与输入、量化版本、候选阈值、CPU/NPU 配置、采集策略和显示提交策略。修改检测质量或其他条件时单独报告，不能把质量下降换来的 fps 提升当作同条件优化。

### 13.3 逐帧时间轴

```text
T_capture_ready         = INPUT_READY - FRAME_SOF
T_wait_dispatch         = DET_START - INPUT_READY
T_service               = RESULT_READY - DET_START
T_process               = T_wait_dispatch + T_service
T_wait_display_boundary = DISPLAY_COMMIT - RESULT_READY
T_scan_offset           = SHOW_FRAME_FIRST - DISPLAY_COMMIT

T_visible = T_capture_ready
          + T_process
          + T_wait_display_boundary
          + T_scan_offset
          = SHOW_FRAME_FIRST - FRAME_SOF
```

以上区间使用同一 frame_id、同一时间基准的事件时间戳。`T_capture_ready` 包含采集、三分支写入排空和就绪发布；检测输入单独写完不代表整帧已就绪。`T_wait_dispatch` 包含 READY 状态等待上一任务释放计算资源及本帧派发的时间，不能从完整处理时间或可见延迟中扣除。`T_wait_display_boundary` 也包含提交排队、握手及错过某次边界后的等待，不默认最多一个扫描周期。

`T_service` 按实际不重叠区间细分为 `T_NPU_total`、`T_CPU_decode_NMS`、`T_avatar_command` 及尚未归入这些项的其他调度/结果发布开销。`T_NPU_total = DET_DONE - DET_START`，包含实际图执行、算子控制和未被重叠掉的 DMA 等待；不能再把这些等待与利用率口径重复计时。各分项合计应与事件差一致，跨域同步误差单独记录。

例如下一帧输入在 t=16 ms 就绪，等待上一任务至 t=40 ms 才开始服务，服务耗时 40 ms，则 `T_wait_dispatch=24 ms`、`T_service=40 ms`、`T_process=64 ms`。预采帧可以提高吞吐，但这 24 ms 排队时间仍计入该帧延迟。

全屏图像从有效 `(0,0)` 开始，不再固定增加旧布局的 150 行/3.96 ms 偏移。`SHOW_FRAME_FIRST` 在输出 RGB/DE 流水末端记录；若 DISPLAY_COMMIT 位于消隐区，`T_scan_offset` 仍含至有效起点的相位及像素流水延迟，必须实测，不能直接置零。

仅用 CPU 的显示提交时刻代替可见时刻会漏掉这些开销。实际计时按输出有效事件测量，而不是仅套算式。

仅作延迟分解示例：假设采集及就绪发布合计 16.5792 ms、无调度排队、服务 25 ms，且显示记录及时被接纳、在紧接着的下一有效画面起点原子提交；边界等待接近 16.5792 ms 时，先不计像素流水延迟，总延迟约 58.16 ms。这里的采集就绪时间、25 ms 服务时间和提交相位均为示例假设，不是包含任意 DDR 背压的上界或强制处理门槛；有排队、写入排空或提交延误时应按事件差计入。保留的 50 ms 延迟优化参考仍需缩短实际等待/处理或约束提交相位；达到 ≥24 fps 也不能据此承诺约一帧延迟。

### 13.4 时钟相位、帧率与截止时间

约 41.67 ms 的平均独立输出间隔，与某帧从输入到显示只停留约 41.67 ms，是两个指标。输入/输出标称同频但相位不同，必须扫描多种相位组合，测量更新间隔、可见延迟和提交等待。

正常优化配置允许在每个满足安全提交条件的输出帧边界接纳新结果，不固定两扫描一次更新。约 60 Hz 扫描下，24 fps 并不对应整数个扫描周期；可能需要不同次数的重复扫描或出现自然的更新间隔变化。不能只为让结果恰好停留两次扫描而人为限制较快的处理通路，也不能将扫描率误记为有效输出率。

测试可设置目标采集率或诊断截止时间，但其值和策略须写入配置。未启用固定时限时，报告更新间隔和重复显示，不默认以 33.3 ms 或 41.67 ms 对每帧作硬实时判罚。显示行 FIFO 供数、输出同步和同帧提交属于正确性约束，不因性能目标放宽而允许失效。

增加缓冲只能吸收有限抖动，不能弥补持续处理时间大于实际接纳周期。取最新结果策略也不能掩盖额外丢帧、不均匀更新或队列延迟。以有效输出帧率提高为目标，同时报告间隔抖动和延迟，不用长期积压换取较高检测吞吐。

### 13.5 时间戳与计数

至少记录以下带 frame_id 的事件：

```text
FRAME_SOF                    # 选中输入帧的有效画面开始
CAPTURE_ACCEPTED
RAW_WRITE_DONE / PREVIEW_WRITE_DONE / INPUT_WRITE_DONE
CAPTURE_DONE / INPUT_READY    # 三分支完成、尺寸检查通过后的同一逻辑就绪事件
DET_START                    # 锁定本帧计算所有权、开始派发首个算子
DET_DONE                     # 本帧最后算子输出写完成，不含 CPU 后处理
RESULT_READY                 # 本帧后处理、头像参数及结果写入完成
DISPLAY_COMMIT               # 安全输出帧边界实际原子锁存参数，记录相对有效画面起点的相位
SHOW_FRAME_FIRST             # 当前 frame_id 首个实际有效输出像素
MODE_REQUEST / MODE_COMMIT    # 另外绑定模式序号；不增加独立输出帧计数
DISPLAY_RELEASE_ACK
```

同时记录 CPU/NPU 周期、显示扫描次数、独立检测/有效输出帧数、主动抽帧、额外丢帧、未显示即丢弃、重复扫描、帧排队、FIFO 错误和复位次数。每个真实处理的 frame_id 首次显示只计一次，模式切换及重复扫描不重复计数。

统一时间基准，跨域事件可靠传递；多位时间戳采用握手或合适编码，不直接跨域采样自由变化的二进制计数器。记录事件同步误差，避免将不同域的周期值直接相减。

板内延迟定义为 `SHOW_FRAME_FIRST - FRAME_SOF`；模式响应延迟另用 MODE_COMMIT−MODE_REQUEST 记录。摄像头曝光、电脑播放、显示器内部处理延迟不包含其中；需要完整交互延迟时另外测，不借用板内数字。

报告完整处理时间、有效输出间隔和板内可见延迟的平均、P50/P95/P99、最大值，并记录稳态整体及固定时间窗口的有效输出 fps。配置了诊断截止时间时，另外报告超期数量及采用的门槛，不能默认套用 30 fps 周期。屏幕和串口只低频更新统计，不因逐帧打印阻塞实时循环。

## 14. 验证计划

### 14.1 正确性层次

| 层次 | 检查 |
|---|---|
| CPU | 六级流水线、ISA/C 跨界、旁路/停顿/冲刷、访存和陷入、中断返回 |
| Cache/BP | 冷启动、两路替换、字节写、写缺失/错误、FENCE.I、预测恢复 |
| NPU 单算子 | signed INT8 边界、DW 通道独立、尾块、padding、跨 K 累加、量化/饱和 |
| NPU 整网 | 固定导出图各层与整数参考一致，跨层张量不提前覆盖 |
| 预处理 | 全画面首末像素、5×5 与 2×2 分组、BGR/RGB、底部补齐、通道对齐 |
| 显示 | 原分辨率全屏及四角/边框、三模式同帧、按键去抖/合并/帧边界、坐标还原、Alpha 极值、裁剪、首行预取和 bank 退休 |
| 帧管理 | 采集完成晚于写响应，切换晚于提交，释放晚于最后消费者访问；下一帧 READY 时，当前图的算子间空闲不得导致计算所有权切换 |
| 并发 | 显示＋头像读取＋NPU＋采集＋CPU 共享 DDR 无静默错误 |

### 14.2 独立测试模型

NPU 未完成时，CPU 使用固定检测输出验证后处理；Video 使用人工框和可配置处理延迟验证全屏、按键模式切换、帧提交/释放与贴图。测试模型只用于开发，完整演示须替换成真实 NPU 结果。

Video 延迟测试覆盖约 5、10、15、20、25、35、40、45、60 ms 以及带抖动的处理完成事件，检查较快运行和低于优化目标时的行为；同时注入模拟 NPU 的 DDR 访问，不能仅靠空等待证明并发性能。较慢工况仍应保持正确扫描、同帧叠加、受控丢帧和无缓冲覆盖，不以达到某个 fps 代替正确性检查。

另覆盖下一帧已 READY、当前图算子间插入停顿的场景，核对 frame_owner、算子顺序及共享工作区保护。时间戳检查分别覆盖无排队、有 READY 等待、三分支写入延后和错过显示边界，要求各分段时间之和等于同帧 `SHOW_FRAME_FIRST - FRAME_SOF`，并单独报告同步误差。

NPU 代表性层要带真实银行缓冲、地址生成、重定标和 DMA，不以裸乘法阵列频率代替完整 NPU。CPU 后处理使用实际六级 CPU 的周期，不以桌面 Python 时间代替。

### 14.3 精度与演示素材

至少覆盖无脸、单正脸、合理范围内侧脸、眼镜/光照变化、脸靠四边、快速移动及多人进入。低输入尺寸导致的漏检与量化导致的差异分开报告。

在同一静态 frame_id 上切换 BOX/AVATAR，主人脸检测框与头像目标必须对应；动态帧更新和模式请求同时到达时仍保证原图/结果/模式原子绑定。素材是预设而非模型生成，表情识别是扩展而非当前功能，文档与现场介绍一致。

角度/遮挡导致的贴图穿帮不自动归为检测错误；当前没有分割或遮挡推理，不能通过剪掉失败片段声称支持相关能力。

### 14.4 验收证据

保留代码提交、工具链/PDS/IP 版本、CPU 配置、模型和素材哈希、输入素材与预处理版本、测试种子、资源/时序报告、UART 统计和演示录像。

阶段 1 连续正常运行至少 10 分钟，不设 24/30 fps 功能验收门槛；阶段 2 至少 30 分钟，并记录 ≥24 fps 优化目标的达成情况及可继续提升空间。另做冷启动、失锁、异常输入、DMA 错误、超时与重初始化测试。录像不替代数值一致性、时序闭合或错误计数记录。

功能验证通过、CPU 特性通过、有效输出帧率与延迟优化目标分别给结论。未达到 ≥24 fps 时继续保留可复现的功能演示版本及瓶颈报告；不得以重复扫描、跳过真实推理或只切换显示效果来宣布目标达成。

## 15. CPU、NPU、Video 三条并行实施路线

### 15.1 并行原则

三条路线从开始同时推进；各自完成仿真、综合、上板与集成准备。下表的阶段是共同交付节点，不要求每行所有模块完成后才允许继续下一行的独立工作。

六级 CPU 不等待 YuNet；模型整数参考和 DW 计算不等待 CPU；Video 不等待真实检测框。接口先冻结，双方就绪就两两集成，不能等全部模块完成才开始验证。

### 15.2 阶段与交付

| 阶段 | CPU 路线 | NPU 路线 | Video 路线 | 共同交付 |
|---|---|---|---|---|
| 阶段 0：接口与基础 | 六级 RTL 回归、板级最小 SoC、UART/Timer/启动；发布地址与 MMIO；立即测 CoreMark | 固定 YuNet、输入形状审计、浮点效果、校准与整数参考；普通/DW 代表层验证 | 固定模式彩条/回环、DDR 自检；全帧及既有预处理；原分辨率全屏、人工框/素材及功能键切换 | 共用头文件、模型/素材清单、板级与逐层报告；互不等待 |

CPU 牵头顶层、互连和软件集成；Video 负责 DDR/HDMI/像素域封装和约束；NPU 负责固定图、整数语义和计算硬件。公共地址、寄存器、模型清单由主责发布，其他路线参与检查。

每条路线保留独立仿真/板测顶层，共用同一份源码和封装，不复制三套 DDR 或协议实现。CPU 的性能测试贯穿所有可运行节点，而非放到整机完成后再测。

| 原始图像 | 保存同帧 800×600 原图、地址、步长和 frame_id | 按检测框动态裁脸硬件 |
| 检测结果 | 人脸框、五点、主人脸索引及有效标志 | 用五点冒充表情分类 |
| NPU | 模型/算子参数由软件配置，通路可复用 | 第二个网络、同时多模型执行 |
| 显示 | avatar_id 与检测位置分开，字段带版本 | 自动表情到素材的映射 |
| 帧所有权 | 保留消费者/阶段概念与释放事件 | 在表情未读完前提前释放原图 |
| 软件状态 | expression_valid=0 和未启用枚举 | 默认填“中性”或虚构置信度 |

### 16.2 后续接入顺序

```text
当前：检测 → 选择主人脸 → 手动/配置 avatar_id → 显示

后续：检测 → 从同帧原图裁脸/缩放 → 表情网络
      → 有效性与状态处理 → avatar_id 映射 → 显示
```

表情模型加入前重新评估处理时间、原图占用、额外 DMA 和响应延迟。显示接口可不变，但有效输出帧率、≥24 fps 优化目标达成情况和低延迟结论必须重新验证；不预先保证新增第二任务没有代价，也不把表情刷新次数混入输出帧率。

新增表情类别表示可见表情估计，不是人的身份或真实心理状态。现阶段模型、数据集和 QAT 训练不作为交付依赖。

## 17. 范围控制与风险处理

| 风险 | 当前处理方法 | 不采用的替代说法 |
|---|---|---|
| 模型低分辨率效果差 | 先在软件排查预处理和脸部像素，再审查输入配置/模型适配 | 不声称任何脸大小都可检测 |
| 深度卷积利用率低 | 检查通道独立映射、窗口供数、银行和并行方式 | 不把全部 DW 放到 CPU 后仍称同一性能 |
| INT8 精度不足 | 找逐层误差、尺度/饱和/概率边界，必要时 QAT | 不把图转换错误靠训练掩盖 |
| 有效输出尚未达到 ≥24 fps | 保留功能版，报告瓶颈、实际输出 fps、间隔抖动、排队与掉帧；按最慢环节继续优化 | 不用 HDMI 扫描率、NPU 单独吞吐或同帧效果切换重复计帧，也不恢复 30 fps 强制门槛 |
| 帧延迟超过目标 | 核对采集、计算、显示提交相位与扫描流水 | 不仅展示 NPU 时间作为端到端延迟 |
| 模式切换撕裂或贴图错帧 | 核对 raw、frame_id、模式序号、同帧参数和安全提交边界 | 不把旧结果贴到新视频上 |
| 贴图边缘或遮挡不自然 | 检查素材锚点、缩放/裁剪与 Alpha，明确二维覆盖边界 | 不称为人物分割或生成式替换 |
| 三缓冲不足 | 仿真占用区间、ACK 和最坏时序，显式丢弃未消费帧或修订缓冲 | 不覆盖正在读取的帧 |
| Cache/BP 尚未稳定 | 演示配置关闭，独立回归后集成 | 不削减基本异常、错误与一致性规则 |
| 某条路线落后 | 使用协议正确的测试模型继续其他路线，两两集成 | 不等待全部真实模块齐备才开展验证 |

当前不再重复设计新检测网络、联合检测表情网络或生成网络。若需要更换 YuNet，必须先列出已验证的不满足项和替换成本，再修订规格，不在 RTL 中暗改结构。

## 19. 当前规格摘要

**CPU：**直接以 RV32IMC_Zicsr 六级单发射为当前验证与演示目标，保留两路 Cache、基础预测、异常中断和持续性能分析；双发射仅作未来方向。

**AI：**一个 YuNet 人脸检测模型，优先保留预训练结构；NPU 支持普通、逐点、深度卷积和图中必要辅助算子；CPU 执行有限候选后处理与头像控制。当前不识别人脸身份或表情。

**视频：**一入一出，固定 800×600 @ 60 Hz、40 MHz；完整原图按原分辨率全屏显示，功能键按帧边界循环 RAW/BOX/AVATAR。检测框和头像采用原图坐标；不预留上下状态栏。KEY0 保留协调复位/重采用途。

**存储：**沿用三帧槽及同槽 raw/preview 分配，320×320 BGR NCHW 检测输入各用 320 KiB 槽；正式显示读取 raw，preview 保留诊断兼容。三模式共用同帧结果，扫描叠加，不生成额外处理后整帧；共享写后读及正式槽所有权另验。

**性能：**30 fps 不作强制要求。先完成真实完整功能，再以**有效输出帧率 ≥24 fps、越高越好**为优化方向；不是固定 24 fps，也不人为限制到 30 fps。模式切换和重复扫描不重复计数，HDMI 保持原固定扫描时序。50 ms 级板内可见延迟保留为独立优化参考，帧率提高不能替代延迟、精度与稳定性验证。

**实施：**阶段 0 平台验证、阶段 1 完整演示、阶段 2 性能优化；CPU、NPU、Video 从开始并行，接口先统一、各自可测、双方先集成，最后完成系统验收。
