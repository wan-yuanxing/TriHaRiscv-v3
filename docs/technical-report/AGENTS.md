# Technical Document Workflow

- 技术文档正文直接维护 latex/chapters/*.tex，不恢复 Markdown 转换或同步流程。
- 架构与功能正文按设计方案撰写，可先于代码实现并使用完成时，不默认加入当前 RTL 基线、尚未实现或仅为规划等状态限定；测试和性能结果仍须依据实际记录。
- 正文面向评审者直接陈述设计、方法和结果，不夹带对话、修改过程、执行历史或为改动辩解的说明；日期、版本追溯与修复记录保存在支撑材料中，正文按技术需要引用。
- 并列测试集使用独立小标题；同一支撑材料目录集中说明一次，不在表前表后重复路径，也不解释表格为何省略路径。
- 文档修改完成后运行 latex/scripts/build.ps1 编译输出 PDF，以编译日志确认结果。
- 默认不将 PDF 渲染成图片，不查看 PDF 页面、预览或截图进行版式检查；仅在用户明确要求时执行。
- 按官方模板从作品名称和摘要开始，不设置独立封面；所有页面使用现有官方原图页眉及下横线。
- 表格使用 longtable 按行跨页，续页重复表题和表头，不使用 minipage 或整表 resizebox 锁页；平台配置表保留单行记录，通过列型和字号控制宽度。
- 仅为正文实际引用的标题、图和表添加 \label，不为未被引用的内容预设标签。
- 正文插图使用 figure[!htbp]，允许在当前位置、页顶、页底或浮动页排版；不使用 center + minipage 固定整幅图的位置。浮动比例与间距在 triha-report.sty 中统一设置。
- 绘图及其文字标注使用本项目的功能名称，不出现 biriscv、biRISC-V 等第三方实现名称。
- draw.io 图形样式中同一属性仅保留一项，text 等命名样式置于显式属性之前；生成样式时按键覆盖，避免重复的 align、fontSize 等属性或样式顺序覆盖用户在界面中的调整。
